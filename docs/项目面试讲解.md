## 1. 项目一句话概括

> 在 **Rockchip RK3568** 边缘设备上，用 **C++17** 搭了一条「**V4L2 摄像头采集 → 稳帧 → RKNN/NPU 目标检测（YOLOv5）→ H.264 编码（MPP 硬编优先）→ RTMP 推流 / MP4 录制**」的多线程实时视频流水线。

**技术栈关键词**：V4L2、DMA-BUF 零拷贝、mmap、NV12、RKNN、NPU、INT8 量化、YOLOv5、RGA 2D 加速、NEON SIMD、MPP 硬编、libx264 软编、FFmpeg 封装、FLV/RTMP、静音 AAC、多线程、有界环形缓冲、条件变量、生产者-消费者、shared_ptr 自定义 deleter、CAS/atomic、单例。

**为什么值得讲**：
- 这是一条**完整、真实、可运行**的边缘 AI 视频流水线，覆盖了嵌入式 + 音视频 + AI 推理 + 网络推流 + 多线程并发的几乎所有核心知识点。
- 用了很多「高性能优化」手段：零拷贝、硬件加速（NPU/RGA/MPP）、NEON、丢帧策略、异步日志，这些都是面试加分项。

## 2. 系统架构总览

### 2.1 模块划分

项目源码在 `src/`（实现）和 `include/vision/`（头文件），全部在 `namespace vision` 下。

| 模块 | 文件 | 职责 |
|------|------|------|
| 类型/配置/调试 | `types.hpp` `config.hpp` `debug.hpp` | Frame（帧）、配置结构体、DEBUG 宏 |
| 采集 | `camera_source.cpp` | V4L2 摄像头采集（dmabuf 零拷贝）/ mp4 文件解码，回调解耦 |
| 推理 | `inferencer.cpp` | RGA 前处理 + RKNN 推理 + YOLOv5 后处理 + NMS + 画框 |
| 编码 | `h264_encoder.cpp`（软编）/ `mpp_encoder.cpp`（硬编） | H.264 编码 |
| 封装/推流/录制 | `muxer.cpp` `rtmp_streamer.cpp` `mp4_recorder.cpp` | FLV/MP4 封装、RTMP 推流（补静音 AAC）、MP4 录制 |
| 协调器 | `pipeline.cpp` | 组合各模块、线程编排、稳帧器、监控 |
| 基础设施 | `logger.cpp` `ring_buffer.hpp` | 日志（异步）、有界环形缓冲 |

### 2.2 线程模型

这是一条**多线程生产者-消费者流水线**，一共 7 个线程：

```
采集线程(采集) ──cap_q──▶ 稳帧线程(pacer) ──inf_q──▶ 推理线程 ──enc_q──▶ 编码线程
                                                          │
                                      ┌───────────────────┴─────────────┐
                                   push_q (推流)                  record_q (录制)
                                      │                               │
                                      ▼                               ▼
                                  推流线程(RTMP)                   录制线程(MP4)
                                                                    + 监控线程(周期打印)
```

每个线程是一个 `while (running_) { ... }` 循环，线程之间**只通过有界环形缓冲（RingBuffer）+ 条件变量**通信，**不共享裸内存**（除了采集零拷贝的帧，后面会讲）。

### 2.3 三大设计原则

1. **回调解耦**：`CameraSource::RegisterFrameCallback` 注册回调，采集线程在回调里**只入队，不做重活**。这样采集模块完全不依赖下游（推理/编码）是谁，换实现不用改采集。
2. **零拷贝**：V4L2 用 `mmap` + `EXPBUF` 导出 DMA-BUF fd，采集**不 memcpy**，Frame 直接引用 mmap 地址；用 `shared_ptr` 自定义 deleter 在引用归零时 `QBUF` 归还 buffer 给内核。
3. **线程通信**：有界环形缓冲 + 条件变量，生产者-消费者，**满则丢最旧**（宁可丢旧帧，不让延迟累积）。

## 3. 数据流从头到尾（一帧的旅程）

以「摄像头检测推流」为例，一帧数据要经历完整链路。面试常问「一帧数据怎么从摄像头到网络」，下面就是标准答案。

```
① IMX415 摄像头 ──MIPI CSI──▶ ISP(3A 白平衡/曝光/增益) ──▶ NV12 数据 ──▶ 内核 DMA buffer
② V4L2 采集线程：poll 等待 → DQBUF 取 buffer → mmap 映射的虚拟地址零拷贝引用 → 构造 Frame → 回调入 cap_q
③ 稳帧线程(pacer)：从 cap_q 取出，按 25fps 节拍输出（快了丢、慢了补帧）→ 入 inf_q
④ 推理线程：RGA 把 NV12 转 RGB + letterbox 缩放 → rknn_inputs_set → rknn_run → 取 INT8 输出
            → NEON 反量化成 float → YOLOv5 解码 + NMS → 得到检测框 → 入 enc_q
⑤ 编码线程：在 NV12 上画框 → 送 H.264 编码器（MPP 硬编优先）→ 得到 AVPacket → 分发到 push_q / record_q
⑥ 推流线程：Muxer 把 H264 包封装成 FLV（补静音 AAC）→ av_interleaved_write_frame → RTMP 协议推到 mediamtx
⑦ 拉流端：VLC/ffplay 连 mediamtx → 拿到 RTMP 流 → 解码播放
```

**关键点**：
- 每一步之间都隔着队列，所以是**异步**的，各阶段速度不一致也不会互相阻塞。
- 队列满了**丢最旧帧**，保证推出去的一定是「最新」的画面，延迟不累积。
- 采集是零拷贝（mmap 引用 DMA buffer），只有稳帧器的 `CloneFrame` 才做一次 memcpy（因为 dmabuf 帧会被归还复用，补帧需要私有副本）。

## 4. 逐模块代码讲解

### 4.1 `main.cpp` — 程序入口

**职责**：信号处理 + 配置加载 + 命令行解析 + 流水线生命周期。

```cpp
std::signal(SIGINT, SignalHandler);   // Ctrl+C 优雅退出
std::signal(SIGTERM, SignalHandler);
std::signal(SIGPIPE, SIG_IGN);        // 忽略 SIGPIPE，RTMP 断开写失败不会让进程挂
```

**面试点**：
- `SIGPIPE`：向已关闭的 socket 写数据时，内核会发 SIGPIPE，默认行为是**终止进程**。这里忽略它，让 `write` 返回 `-1 EPIPE` 由代码处理（推流线程据此重连）。
- 用 `getopt_long` 解析命令行参数，支持 `-c/-d/-W/-H/-f/-s/--no-stream/--no-inference/--record/-v`。
- 主循环 `while (!g_stop) sleep(200ms)` 轮询停止标志，收到信号后调 `pipeline.Stop()` 优雅退出（各线程 join 后才返回）。

### 4.2 `config.cpp` — 自研 YAML 解析器

**职责**：把 `conf/default.yaml` 解析成 `Config` 结构体。**零第三方依赖**（不引 yaml-cpp）。

**核心思路**：
```cpp
// 把 YAML 的缩进层级结构拍平成 "section.key" -> "value" 的 map
capture:            →  capture.source
  source: v4l2          capture.width
  width: 1280
```

实现要点：
- 逐行读文件，`#` 后是注释（先去掉）。
- 用 `find(':')` 找键值分隔，`trim` 去空白，`RemoveQuotes` 去引号。
- 根据**是否有缩进**判断是「section 头」（值空的键）还是「键值对」。
- 用 `std::istringstream >>` 做字符串→数值的自动类型转换（模板 `TryGetValue`）。

**面试点**：这是简化版 YAML，只支持 `key: value` 两层的扁平结构，不支持嵌套数组/锚点等高级特性。够本项目用。

### 4.3 `types.hpp` — 核心数据结构

#### 4.3.1 `Frame` — 视频帧（最重要的类型）

```cpp
struct Frame {
    uint64_t sequence;                // 帧序号（单调递增，追踪生命周期）
    uint32_t width, height;           // 宽高
    TimestampUs capture_timestamp;    // 采集完成时间戳（单调时钟微秒）
    TimestampUs inference_timestamp;  // 推理完成时间戳

    const uint8_t* nv12_data;         // NV12 Y 平面起始地址
    uint32_t nv12_stride;             // 行跨度 bytesperline（可能 != width）

    std::vector<int> dma_fds;         // dmabuf fd（V4L2 零拷贝来源）
    uint32_t buffer_index;            // V4L2 buffer index（QBUF 归还用）
    std::shared_ptr<std::vector<uint8_t>> nv12_cpu;  // CPU 内存（mp4 来源）

    DetectResult detection;           // 检测结果
};
using FramePtr = std::shared_ptr<Frame>;
```

**面试点（Frame 的双来源设计）**：一帧数据有两种来源——
1. **V4L2 摄像头**：`nv12_data` 指向 mmap 的 DMA buffer 虚拟地址，**零拷贝**；`dma_fds` 存导出的 fd；buffer 的归还靠 `shared_ptr` 自定义 deleter（引用归零时 `QBUF`）。
2. **mp4 文件**：FFmpeg 解码到 CPU 内存，`nv12_data` 指向 `nv12_cpu` 持有的 vector。

这样下游（推理/编码）**不关心数据从哪来**，统一用 `nv12_data` 访问。

#### 4.3.2 `PacketPtr` — 编码包

```cpp
struct PacketDeleter {
    void operator()(AVPacket* p) const { av_packet_free(&p); }
};
using PacketPtr = std::shared_ptr<AVPacket>;
inline PacketPtr CreatePacket() { return PacketPtr(av_packet_alloc(), PacketDeleter{}); }
```

**面试点**：把 FFmpeg 的裸指针 `AVPacket*` 包装成 `shared_ptr`，用自定义 deleter 调 `av_packet_free`，实现 RAII（离开作用域自动释放，不用手动 free）。这是「C++ 管理 C 库资源」的经典手法。

#### 4.3.3 `GetCurrentTimestampUs` — 单调时钟

```cpp
inline TimestampUs GetCurrentTimestampUs() {
    struct timespec ts{};
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000000ULL + ts.tv_nsec / 1000ULL;
}
```

**面试点**：用 `CLOCK_MONOTONIC`（单调时钟）而非 `CLOCK_REALTIME`（墙钟）。单调时钟不受系统时间调整（NTP 校时、手动改时间）影响，**测延迟/性能统计必须用它**。

### 4.4 `ring_buffer.hpp` — 有界环形缓冲（线程通信核心）

这是整个流水线解耦的关键。**面试必考**。

```cpp
template <typename T>
class RingBuffer {
    // Push：生产者入队，满则丢最旧（永不阻塞）
    void Push(T item) {
        std::lock_guard<std::mutex> lock(mutex_);
        if (size_ == capacity_) {         // 满了
            head_ = (head_ + 1) % capacity_;  // 丢弃最旧的（head 前移）
            --size_;
            ++dropped_;
        }
        buffer_[tail_] = std::move(item); // 写入尾部
        tail_ = (tail_ + 1) % capacity_;
        ++size_;
        not_empty_.notify_one();          // 唤醒一个消费者
    }

    // Pop：消费者阻塞取出（队列空则休眠）
    bool Pop(T& out) {
        std::unique_lock<std::mutex> lock(mutex_);
        not_empty_.wait(lock, [this]{ return size_ > 0 || closed_; });
        if (size_ == 0) return false;     // 队列空且已关闭
        out = std::move(buffer_[head_]);
        head_ = (head_ + 1) % capacity_;
        --size_;
        return true;
    }
    // PopFor：带超时的取出（稳帧器用）
    // Close：关闭，唤醒所有消费者使其退出
};
```

**面试点**：
- **环形数组**：用固定大小 `vector` + 头尾指针（`head_`/`tail_`），**不动态扩容**，避免高负载下内存分配抖动。
- **有界 + 丢最旧**：视频实时场景，旧帧价值低，宁可丢旧帧也不让延迟累积。这是「低延迟」的关键设计。
- **条件变量**：`not_empty_.wait(lock, predicate)` 阻塞等待，消费者空时休眠不忙轮询（CPU 友好）。用 `unique_lock`（可解锁）+ 谓词避免「虚假唤醒」。
- **Close 优雅退出**：关闭队列时 `notify_all` 唤醒所有阻塞的消费者，`Pop` 返回 false，线程据此退出 `while` 循环。
- **SPSC 语义**：注释里说了「单生产者单消费者」，但内部仍用 mutex（25fps 下锁开销可忽略，换取简单健壮）。

### 4.5 `logger.cpp` — 日志系统

**职责**：全局单例日志，支持**异步写** + **文件轮转**。

**面试点**：

1. **单例（Meyers Singleton）**：
```cpp
Logger& Logger::instance() {
    static Logger inst;   // 局部静态对象，C++11 起线程安全
    return inst;
}
```
C++11 保证函数内局部 static 对象初始化是**线程安全**的（编译器加锁/原子）。这是最简单的单例写法。

2. **异步日志（生产者-消费者）**：`log()` 把格式化好的行 `push` 进 `queue_`（加锁），后台 `workerLoop` 线程 `swap` 出整个队列批量写文件。**减少锁竞争 + 减少 I/O 次数**。用 `batch.swap(queue_)` 一次性换出（swap 不拷贝，O(1)）。

3. **条件变量退出**：`shutdown()` 里 `running_.store(false); cv_.notify_all();`，写线程的 `cv_.wait(lock, predicate)` 醒来发现 `!running_` 退出循环。

4. **文件轮转**：文件超 `max_size_` 后，把 `.N` 重命名为 `.N+1`（从后往前避免覆盖），当前文件重命名 `.1`，重新打开新文件。

5. **变参日志接口**：
```cpp
void Logger::info(const char* fmt, ...) {
    va_list ap; va_start(ap, fmt);
    char body[kMaxLineLen]; std::vsnprintf(body, sizeof(body), fmt, ap);
    va_end(ap);
    log(LogLevel::Info, "%s", body);
}
```
`va_list`/`va_start`/`vsnprintf`/`va_end` 是 C 变参函数的标准用法。

### 4.6 `camera_source.cpp` — 采集（V4L2 零拷贝 + mp4 解码）

**这是「零拷贝」的核心，面试必考。**

#### 4.6.1 V4L2 采集流程（标准五步）

```cpp
open(设备, O_RDWR|O_NONBLOCK)          // ① 打开（非阻塞，配合 poll）
VIDIOC_QUERYCAP                        // ② 查能力（判断 MPLANE 多平面）
VIDIOC_S_FMT(NV12, 720x480)            // ③ 设置格式
VIDIOC_S_PARM(25fps)                   // ④ 设置帧率
VIDIOC_REQBUFS + QUERYBUF + mmap       // ⑤ 申请 buffer + mmap 映射
VIDIOC_EXPBUF                          // ⑥ 导出 DMA-BUF fd（零拷贝给 RGA）
VIDIOC_QBUF（全部入队）→ VIDIOC_STREAMON // ⑦ 开始采集
```

采集循环：`poll` 等 buffer 就绪 → `VIDIOC_DQBUF` 取 buffer → 构造 Frame（零拷贝引用）→ 回调入队。

#### 4.6.2 零拷贝的关键代码

```cpp
// DQBUF 取到 buffer 后，不拷贝数据，直接引用 mmap 地址
FramePtr frame(new Frame, [this, buffer_index](Frame* raw) {
    delete raw;
    ReturnBuffer(buffer_index);   // 引用计数归零时 QBUF 归还 buffer
});
frame->nv12_data = static_cast<const uint8_t*>(mapped.address);  // 指向 mmap 映射的 DMA buffer
frame->nv12_stride = stride_;
frame->dma_fds.push_back(dma_fds_[buffer_index]);   // 导出给 RGA 用的 fd
```

**面试点**：
- **mmap 零拷贝**：V4L2 的 DMA buffer 用 `mmap` 映射到用户空间，`DQBUF` 拿到的 buffer 直接用虚拟地址访问，**不经过 CPU memcpy**。
- **shared_ptr 自定义 deleter**：Frame 的 deleter 在引用计数归零时调 `ReturnBuffer`（`QBUF` 归还给内核），实现「谁最后一个用完谁归还」的 RAII 式 buffer 管理。
- **dmabuf fd**：`EXPBUF` 导出 DMA-BUF fd，可以跨进程/跨设备（RGA、MPP）共享同一块物理内存，**不需要 CPU 拷贝**。

#### 4.6.3 mp4 解码（`source=mp4`）

用 FFmpeg 解码 mp4：`avformat_open_input → avcodec_decode → sws_scale 转 NV12 → 拷贝到 CPU 内存`。分辨率用 **mp4 文件本身的分辨率**（`codec_context_->width/height`），不读配置。帧率也用文件的帧率。

### 4.7 `inferencer.cpp` — RKNN 推理（前处理 + 推理 + 后处理 + 画框）

**这是整个项目最复杂、知识点最多的模块。**

#### 4.7.1 初始化：加载模型 + 查询 IO

```cpp
rknn_init(&ctx, model_path, 0, 0, nullptr);       // 加载 .rknn 模型
rknn_query(ctx, RKNN_QUERY_IN_OUT_NUM, ...);      // 查输入输出数量
rknn_query(ctx, RKNN_QUERY_INPUT_ATTR, ...);      // 查输入尺寸（640x640）
rknn_query(ctx, RKNN_QUERY_OUTPUT_ATTR, ...);     // 查输出属性（含 scale/zp 反量化参数）
```

#### 4.7.2 前处理：RGA 硬件 NV12 → RGB + letterbox

```cpp
rga_buffer_t src = wrapbuffer_virtualaddr(frame->nv12_data, w, h, RK_FORMAT_YCbCr_420_SP, stride, h);
rga_buffer_t dst = wrapbuffer_virtualaddr(rgb_tmp, scaled_w, scaled_h, RK_FORMAT_RGB_888, scaled_w, scaled_h);
imresize(src, dst);   // RGA 硬件做 NV12→RGB 转换 + 缩放，同步执行
```

**面试点**：
- **letterbox**：把不同比例的图等比缩放到 640×640，短边居中，**灰边填充（值 114）**，保持宽高比不变形。推理后要把坐标逆映射回原图（减 padding 除 scale）。
- **RGA 硬件加速**：RK3568 的 2D 加速器，`imresize` 做 NV12→RGB 格式转换 + 缩放，**同步执行**（sync=1），从 CPU 的 ~50ms 降到 ~3ms。
- **wrapbuffer_virtualaddr 参数顺序**（注释特别强调）：`va, width, height, format, wstride, hstride`，容易记错。
- **为什么用虚拟地址而非 fd**：V4L2 的 stride（bytesperline）可能 != width，用虚拟地址能正确处理 stride。但数据实际在 DMA buffer 里，mmap 映射零拷贝。

#### 4.7.3 推理三步曲

```cpp
rknn_inputs_set(ctx, 1, &input);    // 设置输入
rknn_run(ctx, nullptr);             // NPU 推理
rknn_outputs_get(ctx, n, outputs);  // 取输出（INT8）
rknn_outputs_release(ctx, n, outputs); // 释放输出
```

#### 4.7.4 INT8 反量化（NEON 加速）

```cpp
// 反量化公式：float = (int8 - zero_point) * scale
inline float Dequantize(int8_t v, int32_t zp, float scale) {
    return (float(v) - float(zp)) * scale;
}
```

**面试点（量化/反量化）**：
- **INT8 量化**：把 float32 权重/激活量化到 int8，模型体积小 4 倍、NPU 算力更强（RK3568 有 0.8/1 TOPS 的 int8 算力）。
- **反量化**：推理输出的 int8 要用公式 `(int8 - zero_point) * scale` 还原成 float。`scale`（缩放系数）和 `zero_point`（零点）是量化参数，从 `rknn_query(OUTPUT_ATTR)` 拿到。
- **非对称量化**：zero_point 不是 0（本模型 zp≈43~69），所以不能简单 `int8 * scale`，必须减 zp。

**NEON SIMD 加速**（`#if defined(__aarch64__)`）：
```cpp
int8x16_t v8 = vld1q_s8(src + e);       // 一次加载 16 个 int8
int16x8_t v16 = vmovl_s8(...);           // 扩到 int16
int32x4_t v32 = vmovl_s16(...);          // 扩到 int32
float32x4_t f = vcvtq_f32_s32(v32);      // 转 float
f = vmulq_f32(vsubq_f32(f, zp), scale);  // (v - zp) * scale
vst1q_f32(dst + e, f);                   // 存回
```
一次处理 16 个 int8，比标量循环快很多。**面试点**：NEON 是 ARM 的 SIMD 指令集，128 位寄存器，可一次算 4 个 float 或 16 个 int8。

#### 4.7.5 YOLOv5 后处理（解码 + NMS）

YOLOv5 有 **3 个输出头**（stride 8/16/32，对应小/中/大目标），每个网格预测 3 个 anchor，每个 anchor 有 `85` 个值（`4 边框 + 1 目标置信度 + 80 类别`）。

```cpp
float objectness = data[off + 4 * grid_len];      // 目标置信度
if (use_sigmoid) objectness = Sigmoid(objectness);
// 找最大类别分数
float score = objectness * max_class_score;
if (score < confidence_threshold) continue;       // 阈值过滤

// 边框解码
bx = (tx*2 - 0.5 + gx) * stride;                  // 中心点 x
by = (ty*2 - 0.5 + gy) * stride;
bw = pow(tw*2, 2) * anchor_w;                     // 宽（anchor 还原）
bh = pow(th*2, 2) * anchor_h;
```

**面试点**：
- **YOLOv5 输出头**：3 个尺度（stride 8/16/32）负责不同大小的目标，每个网格 3 个 anchor。
- **边框解码公式**：`bx = (sigmoid(tx)*2 - 0.5 + gx) * stride`，这是 YOLOv5 特有的（把预测值限制在网格附近的 ±1.5 个网格内）。
- **anchor**：预定义的先验框宽高（如小目标 10×13、16×30、33×23），预测值是对 anchor 的缩放。
- **use_sigmoid 陷阱**：标准 yolov5s 输出是 logits（需 sigmoid），而 relu/n 版输出已是 sigmoid 后值。**换模型必须同步改配置**，否则阈值失效、候选暴增、后处理慢到 2 秒/帧。
- **NMS（非极大值抑制）**：同一类别按 IoU 抑制重叠框，保留分数最高的。本实现是 O(n²) 的朴素 NMS。

#### 4.7.6 坐标逆映射（letterbox → 原图）

```cpp
x = (bx - bw/2 - pad_x) / scale;   // 减 padding 再除 scale，还原到原图坐标
```

#### 4.7.7 画框 `DrawBoxesOnNv12`

直接在 NV12 的 **Y 平面**画白框（把边框像素的 Y 值设为 255=白色）。只改 Y 不改 UV（所以框是白色/黑色，无色相）。

### 4.8 `h264_encoder.cpp` — libx264 软编

**职责**：NV12 → H.264（用 FFmpeg 的 libx264）。

```cpp
codec_context_->time_base = {1, fps};
codec_context_->max_b_frames = 0;            // 零 B 帧，降延迟
codec_context_->flags |= AV_CODEC_FLAG_GLOBAL_HEADER;  // SPS/PPS 写入 extradata（AVCC）
av_opt_set(priv, "preset", "ultrafast", 0);
av_opt_set(priv, "tune", "zerolatency", 0);  // 零延迟

// 软编：NV12 → YUV420P（sws_scale 格式转换）
sws_scale(sws_ctx, src, src_linesize, 0, height, dst_frame->data, dst_frame->linesize);
dst_frame->pts = pts_++;
avcodec_send_frame(ctx, dst_frame);
avcodec_receive_packet(ctx, packet);
```

**面试点**：
- **max_b_frames=0**：禁用 B 帧。B 帧是双向预测帧，需要参考前后帧，会引入编码延迟。禁用后只有 I/P 帧，延迟低。
- **zerolatency tune**：关掉 lookahead（前瞻），编码器不等后面的帧，实时性最好。
- **AV_CODEC_FLAG_GLOBAL_HEADER**：把 SPS/PPS 放到 `extradata`（AVCC 格式），而不是塞进码流（Annex-B）。FLV/RTMP 需要 AVCC（长度前缀）格式。
- **NV12 → YUV420P**：libx264 吃 YUV420P（planar 三平面），而采集是 NV12（Y + 交错 UV 两平面），用 sws_scale 转换。
- **帧率/时间基**：`time_base = {1, fps}`，pts 就是帧序号（0,1,2...），每帧 1/fps 秒。

### 4.9 `mpp_encoder.cpp` — MPP 硬件编码

**职责**：NV12 → H.264（用 Rockchip MPP 硬件编码器）。

**面试点（MPP）**：
- **MPP = Media Process Platform**，Rockchip 的媒体处理平台，屏蔽芯片差异的统一 API（MPI）。
- 流程：`mpp_create → mpp_init(ENC, AVC) → 配置(宽高/码率/gop/fps) → 编码循环(put_frame → get_packet)`。
- 配置用 `mpp_enc_cfg_set_s32(cfg, "rc:bps_target", bitrate)` 这种「字符串 key + 值」的方式。
- 输入 NV12（`MPP_FMT_YUV420SP`），输出 H.264。
- **Annex-B → AVCC**：MPP 输出的是 Annex-B 码流（`00 00 00 01` 起始码），要转成 AVCC（4 字节长度前缀）才能给 FLV/RTMP 用。`ParseAnnexB` 按起始码切 NAL，`EmitAnnexBPacket` 加长度前缀。
- **性能**：实测 enc≈4ms、CPU≈5%（软编 15~25ms、CPU 35~40%），大幅省 CPU。

### 4.10 `muxer.cpp` — 封装（FLV/MP4）

**职责**：把 H.264 包封装成 FLV（RTMP）或 MP4（录制）。

**面试点**：
- 用 `avformat_alloc_output_context2` + `avformat_new_stream` + `avio_open` + `avformat_write_header` 标准 FFmpeg 封装流程。
- **静音 AAC 轨**：mediamtx v1.9.3 不转发「纯视频无音频」的 RTMP 流（拉流端 0 帧），所以 FLV 要补一路静音 AAC。静音帧是**硬编码字节**（ffmpeg CLI 预生成），不用板端 AAC 编码器（版本错配会段错误）。
- **时间戳对齐**（`WriteSilentAudio`）：音频 pts 必须跟视频对齐，且要 `av_packet_rescale_ts` 换算到 FLV 的毫秒 time_base。否则音频时间戳比视频大 ~44 倍，A/V 错位，拉流端长时间缓冲。
- **拉流地址日志**：`GetLanIp` 用 `getifaddrs` 取本机非回环 IPv4，推流地址是 127.0.0.1 时补打一行 `rtmp://<LAN_IP>:1935/live/stream` 方便跨机器拉流。

### 4.11 `rtmp_streamer.cpp` — 推流 + 断线重连

**职责**：把 H.264 包经 Muxer 封装成 FLV，通过 RTMP 推到服务器；断线自动重连。

```cpp
bool RtmpStreamer::Push(const PacketPtr& packet) {
    if (!muxer_.IsOpen()) {
        if (!config_.reconnect || 超过最大重连次数) return false;
        if (reconnect_count_ > 0) sleep(reconnect_delay_ms);  // 仅重连时等待
        if (!Open()) { ++reconnect_count_; return false; }
    }
    if (muxer_.Push(packet)) { reconnect_count_ = 0; return true; }
    muxer_.Close();   // 写失败则关闭，下次 Push 时重连
    return false;
}
```

**面试点**：
- **懒打开**：Muxer 首包时才打开（此时编码器的 SPS/PPS extradata 才就绪）。
- **断线重连**：写失败 → 关闭 Muxer → 下次 Push 检测到未打开 → 等待后重连。
- **首连不 sleep**：`reconnect_count_ > 0` 才等待，否则首次连接会白睡 2s，导致时间戳跳变、拉流端缓冲。

### 4.12 `pipeline.cpp` — 协调器（核心调度）

**职责**：组合各模块、创建线程、组织数据流。

#### 4.12.1 Initialize：打开各模块

```cpp
if (config_.encode.hardware) {
    mpp_encoder_ = make_unique<MppEncoder>();

    else mpp_encoder_.reset();   // 回退
}
```


#### 4.12.3 PacerLoop：稳帧器

```cpp
while (running_) {
    // 按 25fps 节拍等待
    bool got = capture_queue_.PopFor(fresh_frame, wait);
    if (got) { last_frame = CloneFrame(fresh_frame); has_last = true; }
    if (now >= next_emit) {
        output = got ? fresh_frame : (has_last ? CloneFrame(last_frame) : null);
        if (output) inference_queue_.Push(std::move(output));
        next_emit += period;
    }
}
```

**面试点**：
- **稳帧器作用**：以单调时钟为基准，按目标帧率（25fps）**恒定节拍**输出，消除采集抖动。
- **补帧**：某周期没新帧，复制上一帧（`allow_duplicate`），维持恒定帧率。
- **丢帧**：采集快于目标帧率，有界队列丢最旧自然丢弃。
- **CloneFrame**：因为零拷贝帧（dmabuf）会被归还复用，补帧需要**深拷贝**一份私有副本（`memcpy` NV12 数据），避免和下游共享同一块 buffer 造成竞争。

#### 4.12.4 EncodeLoop：画框 + 编码 + 分发

```cpp

```

`DispatchPacket` 首帧时拿到 extradata（SPS/PPS）打开推流/录制，然后把包分发给 push_q/record_q。

#### 4.12.5 MonitorLoop：监控

周期读 `/proc/stat`（CPU）、`/proc/meminfo`（内存）、`/sys/class/thermal`（温度），打印性能统计。

#### 4.12.6 Stop：优雅退出

```cpp

capture_queue_.Close();     // 关队列唤醒各线程
...join 所有线程...
```

**面试点**：**优雅退出**——先停采集，再 `Close` 各队列（`notify_all` 唤醒阻塞的消费者），各线程 `join` 后才释放资源。顺序不能乱（先上游后下游）。

## 5. C++ 语法点讲解

这一节把项目里用到的、可能不熟的 C++ 语法/特性逐个讲清楚。

### 5.1 `std::shared_ptr` 自定义 deleter

```cpp
FramePtr frame(new Frame, [this, buffer_index](Frame* raw) {
    delete raw;
    ReturnBuffer(buffer_index);   // 额外动作：归还 buffer
});
```

**作用**：`shared_ptr` 除了释放对象（`delete raw`），还能在 deleter 里**执行额外动作**（这里是把 V4L2 buffer QBUF 还给内核）。这是「引用计数归零时自动做清理」的关键，避免手动管理 buffer 生命周期。

**为什么不用普通 delete**：普通 `shared_ptr<Frame>` 只会 `delete frame`，但 Frame 的 dmabuf 还需要 QBUF 归还，所以必须自定义 deleter。

### 5.2 `std::atomic` 和 CAS（无锁）

```cpp
std::atomic<bool> running_{false};
running_.store(true);
bool old = running_.exchange(false);   // 原子交换（读旧值 + 写新值）
running_.load();
```

**作用**：`std::atomic` 保证多线程读写**原子性**（不会数据竞争），`store/load/exchange` 等操作内部用 CPU 的原子指令（如 ARM 的 `LDXR/STXR`，x86 的 `LOCK CMPXCHG`）。

**CAS（Compare-And-Swap，比较并交换）**：`exchange` 的底层就是 CAS。CAS 是「无锁编程」的基础原语：先比较内存值是否是期望值，是则更新，不是则失败重试。项目里 `running_` 标志、`frame_sequence_++`、性能计数都用 atomic。

**面试点**：`std::atomic` 是**无锁**的（对整型/指针通常直接用 CPU 原子指令，不加 mutex），比 mutex 开销小，适合「单个变量」的并发访问。但复杂操作（多个变量一起改）还是要用 mutex。

### 5.3 `std::function` + lambda（回调解耦）

```cpp
// 声明：接受一个 FramePtr 参数、无返回值的回调
void RegisterFrameCallback(std::function<void(FramePtr)> callback);

// 使用：lambda 捕获 this
camera_source_.RegisterFrameCallback([this](FramePtr frame) {
    OnFrameCaptured(std::move(frame));   // 回调里只入队
});
```

**作用**：`std::function` 是「可调用对象」的类型擦除容器，可以装函数指针、lambda、仿函数。配合 lambda（`[this](...)` 捕获 this 指针），实现**回调解耦**——采集模块不知道下游是谁，只调注册进来的回调。

### 5.4 `std::mutex` + `std::condition_variable`（线程同步）

```cpp
std::unique_lock<std::mutex> lock(mutex_);
not_empty_.wait(lock, [this]{ return size_ > 0 || closed_; });
```

**作用**：条件变量让消费者在「队列空」时**休眠**（释放锁，不占 CPU），生产者入队后 `notify_one` 唤醒。`wait(lock, predicate)` 用谓词避免「虚假唤醒」（spurious wakeup，即被唤醒但条件并不满足）。

**面试点**：`wait` 三步：① 原子地释放锁并阻塞；② 被 notify 唤醒；③ 重新加锁并检查谓词。用 `unique_lock` 而非 `lock_guard`，因为 `unique_lock` 可以手动 `lock/unlock`（`wait` 内部要解锁）。

### 5.5 有界环形缓冲（环形数组）

```cpp
head_ = (head_ + 1) % capacity_;  // 环形：取模回绕
```

**作用**：固定大小的数组 + 头尾指针，用**取模**实现环形回绕。满时丢最旧（head 前移），实现「有界」队列。

**面试点**：环形缓冲 vs 普通 deque——环形数组不动态扩容、无内存碎片、缓存友好（连续内存）。用 `%` 取模（或 `& (capacity-1)` 当 capacity 是 2 的幂时更快）。

### 5.6 `std::unique_ptr`（独占所有权）

```cpp
std::unique_ptr<Inferencer> inferencer_;
std::unique_ptr<MppEncoder> mpp_encoder_;
```

**作用**：`unique_ptr` 独占所有权，不可拷贝，只能 move。用于「可选的/可替换的」成员（如硬编 vs 软编二选一）。

### 5.7 变参函数（`va_list`）

```cpp
void Logger::info(const char* fmt, ...) {
    va_list ap; va_start(ap, fmt);   // ap 指向第一个可变参数
    std::vsnprintf(body, sizeof(body), fmt, ap);  // 格式化到缓冲
    va_end(ap);                       // 清理
}
```

**作用**：实现 `printf` 风格的可变参数日志接口。

### 5.8 Meyers 单例（局部静态对象）

```cpp
Logger& Logger::instance() {
    static Logger inst;
    return inst;
}
```

**作用**：函数内 static 对象首次调用时构造，C++11 起线程安全。这是最简单、最安全的单例写法。

### 5.9 `std::move` / 右值引用（移动语义）

```cpp
capture_queue_.Push(std::move(frame));   // 移动 FramePtr，不拷贝（引用计数 +1 而非深拷贝）
out = std::move(buffer_[head_]);         // 移动出队
batch.swap(queue_);                       // swap 不拷贝
```

**作用**：`std::move` 把左值转右值，触发移动构造/赋值，**避免深拷贝**。对 `shared_ptr` 移动只是转移指针所有权（引用计数不变），比拷贝（引用计数 +1）更高效。

### 5.10 `std::atomic` + 性能统计（无锁计数器）

```cpp
struct PerfStats {
    std::atomic<int64_t> total_frames{0};
    std::atomic<int64_t> dropped_frames{0};
};
perf_stats_.total_frames.fetch_add(1);   // 原子自增
```

**面试点**：`fetch_add` 是原子的「读+加+写」，多线程同时自增不丢失。

## 6. 技术栈知识点

### 6.1 V4L2（Video4Linux2）

Linux 的视频采集框架。核心概念：
- **设备节点** `/dev/videoX`。
- **ioctl** 控制：`QUERYCAP`（能力）、`S_FMT`（格式）、`S_PARM`（帧率）、`REQBUFS`（申请 buffer）、`QUERYBUF`（查 buffer）、`QBUF/DQBUF`（入队/出队）、`STREAMON/OFF`（开/停流）。
- **内存映射**：`mmap` 映射内核 DMA buffer 到用户空间，零拷贝。
- **多平面（MPLANE）**：`V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE`，rkisp 用多平面 API。

### 6.2 DMA-BUF 零拷贝

- **DMA（Direct Memory Access）**：硬件直接读写内存，不经过 CPU。
- **DMA-BUF**：Linux 的 buffer 共享框架，用 fd 跨设备共享同一块物理内存。
- **零拷贝**：数据从摄像头 DMA buffer 一路到 RGA/MPP，都引用同一块物理内存，**CPU 不参与拷贝**。
- **EXPBUF**：V4L2 的 ioctl，把 buffer 导出成 DMA-BUF fd。

### 6.3 NV12 / YUV420P 色彩格式

- **YUV**：亮度（Y）+ 色度（U/V）分离。人眼对亮度敏感、对色度不敏感，所以色度可以下采样。
- **NV12**：Y 平面 + 交错的 UV 平面（两平面）。V4L2 采集常用。
- **YUV420P（I420）**：Y + U + V 三个平面（三平面）。libx264 吃这个。
- **420 下采样**：4:2:0，色度水平垂直都 1/2 采样，数据量是 RGB 的一半。

### 6.4 RKNN / NPU / 量化

- **NPU**：神经网络处理器，RK3568 有 1 TOPS 的 int8 算力，专为神经网络优化（大量乘加运算）。
- **RKNN**：Rockchip 的推理框架，`.rknn` 是量化后的模型格式。
- **量化**：float32 → int8，模型体积 1/4、算力提升、精度略降。有对称/非对称量化。
- **反量化**：`float = (int8 - zero_point) * scale`。

### 6.5 RGA（2D 加速器）

Rockchip 的 2D 加速器，能做图像格式转换、缩放、旋转、裁剪。`im2d` 是它的高层 API（`imresize` 等）。

### 6.6 MPP（Media Process Platform）

Rockchip 的媒体处理平台，统一 API 屏蔽芯片差异。能做 H.264/H.265 硬件编解码。`MppCtx` + `MppApi` 结构。

### 6.7 FFmpeg 封装

- `avformat_alloc_output_context2` 分配输出上下文。
- `avformat_new_stream` 创建流。
- `avio_open` 打开输出（文件/RTMP URL）。
- `avformat_write_header` / `av_interleaved_write_frame` / `av_write_trailer`。

### 6.8 RTMP / FLV / AAC

- **RTMP**：Adobe 的实时消息协议，基于 TCP，用于直播推流。
- **FLV**：RTMP 的封装格式，时间戳毫秒精度。
- **AAC**：音频编码，RTMP 推流需要音频轨（mediamtx 纯视频不转发）。
- **AVCC vs Annex-B**：AVCC 用 4 字节长度前缀，Annex-B 用 `00 00 00 01` 起始码。FLV 要 AVCC。

### 6.9 多线程并发

- **生产者-消费者**：用有界队列解耦，满则丢最旧/阻塞。
- **条件变量**：`wait(lock, predicate)` + `notify_one/all`。
- **互斥锁**：`std::mutex` + `lock_guard`/`unique_lock`。
- **无锁**：`std::atomic` + CAS。
- **优雅退出**：`running_` 标志 + `Close()` 唤醒 + `join()`。

### Q2：怎么做到零拷贝的？拷贝发生在哪里？

- 采集：V4L2 `mmap` + `EXPBUF`，DQBUF 的 buffer 直接用 mmap 虚拟地址引用，不拷贝。
- 前处理：RGA 用虚拟地址（mmap 映射的 DMA buffer），不拷贝。
- **唯一一次拷贝**：稳帧器 `CloneFrame`（补帧需要私有副本，因为 dmabuf 会被归还复用）。

### Q3：为什么用有界队列？为什么满则丢最旧？

实时视频场景，**延迟比完整性重要**。旧帧价值低，宁可丢旧帧也不让延迟累积。有界避免内存无限增长。

### Q4：为什么推流要补静音 AAC？

mediamtx v1.9.3 不转发「纯视频无音频」的 RTMP 流（拉流端 0 帧）。补一路静音 AAC 满足「含音频轨」的要求。

### Q5：硬编和软编的区别？为什么硬编优先？

- 软编（libx264）：CPU 编码，灵活、跨平台，但 CPU 占用高（35~40%）、延迟较高（15~25ms）。
- 硬编（MPP）：专用硬件编码器，CPU 占用低（~5%）、延迟低（~4ms），但依赖特定芯片。
- 策略：`encode.hardware=true` 时硬编优先，打不开自动回退软编。

### Q6：为什么 MPP 输出要转 AVCC？

MPP 输出 Annex-B（`00 00 00 01` 起始码），FLV/RTMP 要 AVCC（长度前缀）。所以 `ParseAnnexB` 切 NAL + `EmitAnnexBPacket` 加长度前缀。

### Q7：怎么做到优雅退出？

`running_.store(false)` → 停采集 → `Close` 各队列（notify_all 唤醒）→ 各线程 `join` → 释放资源。顺序先上游后下游。

### Q8：单例怎么保证线程安全？

Meyers 单例（函数内 static 对象），C++11 起初始化是线程安全的。

### Q9：异步日志的原理？

生产者（`log()`）把行 push 进队列，消费者（`workerLoop`）`swap` 出整个队列批量写文件，减少锁竞争和 I/O 次数。

### Q10：letterbox 是什么？为什么需要？

把不同比例图等比缩放到模型输入（640×640），短边居中、灰边填充，保持宽高比不变形。推理后要逆映射（减 padding 除 scale）还原坐标。

### Q11：INT8 量化和反量化？

模型 float32 权重量化成 int8（体积 1/4、算力提升）。反量化 `float = (int8 - zero_point) * scale`。scale/zp 从 `rknn_query` 拿到。

### Q12：为什么用 CLOCK_MONOTONIC 而不是 CLOCK_REALTIME？

单调时钟不受系统时间调整影响，测延迟/性能统计必须用它，否则改时间会导致测量值跳变。

### Q13：生产者-消费者怎么避免忙轮询？

条件变量 `wait(lock, predicate)`，队列空时休眠（不占 CPU），生产者入队 `notify_one` 唤醒。

### Q14：B 帧为什么影响延迟？

B 帧是双向预测帧，需要参考前后帧，编码器要等后续帧才能编 B 帧，引入延迟。禁用 B 帧（max_b_frames=0）实时性更好。

# 07 — 协调器（Pipeline 线程编排）

本篇讲 `src/pipeline.cpp`，这是整个流水线的**大脑**——组合各模块、创建线程、组织数据流。

---

## 7.1 成员变量（队列和线程）

```cpp
class Pipeline {
    Config config_;
    CameraSource camera_source_;
    std::unique_ptr<Inferencer> inferencer_;      // 推理（可选）
    H264Encoder encoder_;                          // 软编
    std::unique_ptr<MppEncoder> mpp_encoder_;      // 硬编
    bool use_hardware_ = false;                    // 是否用硬编
    std::unique_ptr<RtmpStreamer> rtmp_streamer_;
    std::unique_ptr<Mp4Recorder> mp4_recorder_;

    // 有界环形缓冲（各阶段之间通信）
    RingBuffer<FramePtr>  capture_queue_{8};      // 采集 → 稳帧
    RingBuffer<FramePtr>  inference_queue_{8};    // 稳帧 → 推理
    RingBuffer<FramePtr>  encode_queue_{8};       // 推理 → 编码
    RingBuffer<PacketPtr> push_queue_{16};        // 编码 → 推流
    RingBuffer<PacketPtr> record_queue_{64};      // 编码 → 录制

    std::thread pacer_thread_, inference_thread_, encode_thread_,
                push_thread_, record_thread_, monitor_thread_;

    std::atomic<bool> running_{false};
    uint64_t frame_sequence_ = 0;                 // 帧序号
    std::vector<uint8_t> extradata_;              // SPS/PPS 副本
    bool extradata_ready_ = false;
};
```

**逐行讲解**：
- 队列容量：`capture/inference/encode` 都是 8，`push` 16，`record` 64。容量越大能容忍更多突发，但延迟越高（队列里堆积的帧是"延迟"）。
- `inferencer_` 是 `unique_ptr`（可空，`--no-inference` 时为空）；`mpp_encoder_` 也是（可空，回退软编时为空）。
- `frame_sequence_`：帧序号，单调递增，用于追踪生命周期（debug）。

## 7.2 Initialize（打开各模块）

```cpp
bool Pipeline::Initialize() {
    // 1. 打开采集
    camera_source_.Initialize(config_.capture);
    width_ = camera_source_.GetWidth();
    height_ = camera_source_.GetHeight();
    fps_ = camera_source_.GetFrameRate();

    // 2. 注册采集回调（回调解耦：回调里只入队）
    camera_source_.RegisterFrameCallback(
        [this](FramePtr frame) { OnFrameCaptured(std::move(frame)); });

    // 3. 创建推理器（失败降级为无推理）
    if (config_.inference.enabled) {
        inferencer_ = std::make_unique<Inferencer>(config_.inference);
        if (!inferencer_->Initialize()) {
            warn("inference init failed, running without detection");
            inferencer_.reset();      // 降级
        }
    }

    // 4. 打开编码器（硬编优先，失败回退软编）
    if (config_.encode.hardware) {
        mpp_encoder_ = std::make_unique<MppEncoder>();
        if (mpp_encoder_->Open(...)) use_hardware_ = true;
        else { warn("MPP failed, fallback libx264"); mpp_encoder_.reset(); }
    }
    if (!use_hardware_ && !encoder_.Open(...)) return false;
}
```

**逐行讲解**：
- **回调解耦**：`RegisterFrameCallback(lambda)` 注册回调。lambda `[this](FramePtr f){ OnFrameCaptured(move(f)); }` 捕获 this，把帧交给 `OnFrameCaptured`（里面只入队）。
- **降级设计**：推理初始化失败 → 降级为"无推理只推流"；硬编失败 → 回退软编。**优雅降级**保证核心功能（推流）始终可用。
- **硬编优先**：`config_.encode.hardware=true` 先试 MPP，打不开回退 libx264。

### 7.2.1 OnFrameCaptured（采集回调，只入队）

```cpp
void Pipeline::OnFrameCaptured(FramePtr frame) {
    const uint64_t sequence = frame_sequence_++;
    frame->sequence = sequence;               // 打上递增序号
    capture_queue_.Push(std::move(frame));    // 只入队，不做重活
}
```

**逐行讲解**：回调里**只做两件事**：打序号 + 入队。这是"回调解耦"的体现——采集回调不碰推理/编码，避免阻塞采集线程（采集线程阻塞会导致丢帧）。

## 7.3 Start（创建线程）

```cpp
bool Pipeline::Start() {
    camera_source_.Start();                     // 先启动采集
    running_.store(true);

    pacer_thread_     = std::thread(&Pipeline::PacerLoop, this);
    inference_thread_ = std::thread(&Pipeline::InferenceLoop, this);
    encode_thread_    = std::thread(&Pipeline::EncodeLoop, this);
    if (config_.stream.enabled)  push_thread_   = std::thread(&Pipeline::PushLoop, this);
    if (config_.record.enabled)  record_thread_ = std::thread(&Pipeline::RecordLoop, this);
    monitor_thread_   = std::thread(&Pipeline::MonitorLoop, this);
}
```

**逐行讲解**：先 `camera_source_.Start()`（STREAMON + 启动采集线程），再创建下游各线程。`std::thread(&Pipeline::MemberFunc, this)` 用成员函数作线程入口，要传 `this`。推流/录制线程按配置条件创建。

## 7.4 PacerLoop（稳帧器）

```cpp
void Pipeline::PacerLoop() {
    const uint32_t fps = config_.pacer.target_fps;     // 25
    const auto period = std::chrono::nanoseconds(1000000000LL / fps);   // 40ms
    auto next_emit = Clock::now() + period;

    FramePtr last_frame;
    bool has_last = false;

    while (running_.load()) {
        auto now = Clock::now();
        auto wait = duration_cast<ms>(next_emit - now);   // 距离下个节拍的时间
        if (wait.count() < 0) wait = ms(0);

        FramePtr fresh_frame;
        bool got = capture_queue_.PopFor(fresh_frame, wait);   // 最多等 wait 毫秒

        if (got) {
            last_frame = CloneFrame(fresh_frame);   // 深拷贝备份（供补帧）
            has_last = true;
        }

        now = Clock::now();
        if (now >= next_emit) {                      // 到节拍点了
            FramePtr output;
            if (got) output = fresh_frame;                        // 有新鲜帧直接输出
            else if (has_last && allow_duplicate) output = CloneFrame(last_frame);  // 补帧
            if (output) inference_queue_.Push(std::move(output));

            next_emit += period;                     // 推进到下个节拍
            if (next_emit <= Clock::now()) next_emit = Clock::now() + period;  // 防追帧
        }
    }
}
```

**逐行讲解（稳帧器的三个作用）**：
1. **节拍**：`next_emit` 是下个节拍时刻，每 40ms 输出一帧，**恒定帧率**（消除采集抖动）。
2. **补帧**：某周期没等到新帧（`got=false`），用上一帧补（`CloneFrame(last_frame)`），维持帧率。
3. **丢帧**：采集快于目标帧率，有界队列丢最旧自然丢弃。
- **CloneFrame（深拷贝）**：因为零拷贝帧（dmabuf）会被归还复用，补帧需要**深拷贝**一份私有副本（memcpy NV12），避免和下游共享同一块 buffer 造成竞争。
- **防追帧**：`next_emit <= now` 说明落后了，直接对齐当前时间，避免疯狂追帧（雪崩）。

## 7.5 InferenceLoop（推理线程）

```cpp
void Pipeline::InferenceLoop() {
    while (running_.load()) {
        FramePtr frame;
        if (!inference_queue_.Pop(frame)) break;   // 队列关闭则退出

        if (inferencer_) {                          // 有推理器才推理
            const uint64_t start_us = GetCurrentTimestampUs();
            inferencer_->Detect(frame);             // 检测结果写回 frame->detection
            perf_stats_.inference_us.store(GetCurrentTimestampUs() - start_us);
        }
        encode_queue_.Push(std::move(frame));       // 不管有没有推理都往下传
    }
}
```

**逐行讲解**：`inferencer_` 为空（`--no-inference`）时直接透传（不推理）。推理耗时记入 `perf_stats_` 供监控。

## 7.6 EncodeLoop（编码线程）

```cpp
void Pipeline::EncodeLoop() {
    while (running_.load()) {
        FramePtr frame;
        if (!encode_queue_.Pop(frame)) break;

        // 画检测框（就地修改 NV12）
        DrawBoxesOnNv12(frame->nv12_data, frame->width, frame->height,
                        frame->nv12_stride, frame->detection);

        const uint64_t start_us = GetCurrentTimestampUs();
        if (use_hardware_)
            mpp_encoder_->Encode(frame, [this](p){ DispatchPacket(p); });
        else
            encoder_.Encode(frame, [this](p){ DispatchPacket(p); });
        perf_stats_.encode_us.store(GetCurrentTimestampUs() - start_us);
        perf_stats_.total_frames.fetch_add(1);
    }
    // 冲刷编码器残留帧
    if (use_hardware_) mpp_encoder_->Flush(...); else encoder_.Flush(...);
}
```

**逐行讲解**：
- 画框 + 编码：先 `DrawBoxesOnNv12` 就地画框，再编码。
- `use_hardware_` 决定用硬编还是软编（接口一致，下游无感）。
- 编码回调 `DispatchPacket` 把包分发到推流/录制队列。
- 循环结束后 `Flush` 冲刷编码器残留帧。

### 7.6.1 DispatchPacket（首帧打开推流/录制）

```cpp
void Pipeline::DispatchPacket(const PacketPtr& packet) {
    if (!extradata_ready_) {                         // 首个包
        extradata_ready_ = true;
        // 拿 SPS/PPS（此时编码器 extradata 才就绪）
        const uint8_t* ed = use_hardware_ ? mpp_encoder_->GetExtradata() : encoder_.GetExtradata();
        extradata_.assign(ed, ed + size);

        if (config_.stream.enabled) {
            rtmp_streamer_ = make_unique<RtmpStreamer>(config_.stream);
            rtmp_streamer_->SetVideoParameters(width_, height_, fps_, bitrate, extradata...);
        }
        if (config_.record.enabled) {
            mp4_recorder_ = make_unique<Mp4Recorder>(config_.record);
            mp4_recorder_->Open(...);
        }
    }
    if (config_.stream.enabled) push_queue_.Push(packet);      // 分发
    if (config_.record.enabled) record_queue_.Push(packet);
}
```

**逐行讲解**：**懒初始化**——首帧编码后才拿到 SPS/PPS（extradata），此时才创建推流/录制器（它们的 Open 需要 extradata）。之后每个包分发到 push/record 队列。

## 7.7 PushLoop / RecordLoop（推流/录制线程）

```cpp
void Pipeline::PushLoop() {
    while (running_.load()) {
        PacketPtr packet;
        if (!push_queue_.Pop(packet)) break;
        if (rtmp_streamer_ && rtmp_streamer_->Push(packet)) {
            perf_stats_.pushed_frames.fetch_add(1);
        }
    }
}
void Pipeline::RecordLoop() {
    while (running_.load()) {
        PacketPtr packet;
        if (!record_queue_.Pop(packet)) break;
        if (mp4_recorder_ && mp4_recorder_->Push(packet)) {
            perf_stats_.recorded_frames.fetch_add(1);
        }
    }
}
```

**逐行讲解**：两个线程几乎一样，都是"取包 → 推/写 → 计数"。断线重连在 RtmpStreamer 内部处理。

## 7.8 MonitorLoop（监控）

```cpp
void Pipeline::MonitorLoop() {
    while (running_.load()) {
        // 分段 sleep 200ms，周期检查退出（共 monitor_interval_ms）
        for (int wait = 0; wait < monitor_interval_ms && running_; wait += 200)
            sleep_for(200ms);

        // 读 /proc/stat 算 CPU 使用率
        ReadCpuStat(total, idle);
        cpu = 100.0 * (1.0 - delta_idle / delta_total);   // CPU = 1 - 空闲占比
        ReadMemoryUsage(memory);   // /proc/meminfo
        ReadTemperature(temp);     // /sys/class/thermal

        log("monitor: cpu=%.1f%% mem=%.1f%% temp=%.1fC | enc=%lldms inf=%lldms | frames=%lld drop=%lld push=%lld rec=%lld", ...);
    }
}
```

**逐行讲解**：
- 分段 sleep 200ms，让监控线程也能周期检查退出标志。
- **CPU 使用率计算**：读 `/proc/stat` 第一行（cpu 累计时间），两次采样差值算 `(1 - idle_delta/total_delta)`。
- 内存读 `/proc/meminfo`，温度读 `/sys/class/thermal/thermal_zone*/temp`。
- 打印各阶段耗时和计数（enc/inf 延迟、帧数、丢帧、推流、录制）。

## 7.9 Stop（优雅退出）

```cpp
void Pipeline::Stop() {
    if (!running_.exchange(false)) return;   // 幂等：已停止则返回

    camera_source_.Stop();                   // 1. 停采集

    capture_queue_.Close();                  // 2. 关上游队列，唤醒稳帧/推理/编码线程
    inference_queue_.Close();
    encode_queue_.Close();
    if (pacer_thread_.joinable())     pacer_thread_.join();
    if (inference_thread_.joinable()) inference_thread_.join();
    if (encode_thread_.joinable())    encode_thread_.join();

    push_queue_.Close();                     // 3. 关下游队列
    record_queue_.Close();
    if (push_thread_.joinable())   push_thread_.join();
    if (record_thread_.joinable()) record_thread_.join();
    if (monitor_thread_.joinable()) monitor_thread_.join();

    if (use_hardware_) mpp_encoder_->Close(); else encoder_.Close();  // 4. 释放资源
    if (rtmp_streamer_) rtmp_streamer_->Close();
    if (mp4_recorder_)  mp4_recorder_->Close();
}
```

**逐行讲解（优雅退出的顺序，面试重点）**：
1. `running_.exchange(false)`：原子交换（读旧值 + 写 false），幂等（重复 Stop 只执行一次）。
2. **先停采集**（STREAMOFF + join 采集线程），不再产生新帧。
3. **关闭上游队列**（`capture/inference/encode`）：`Close()` 里 `notify_all` 唤醒阻塞的消费者，各线程 `Pop` 返回 false 退出循环。
4. **join 上游线程**：等稳帧/推理/编码线程真正退出。
5. **关闭下游队列 + join**：推流/录制/监控线程。
6. **释放资源**：编码器、推流、录制器。

**关键顺序**：先上游后下游。先停采集（源头），再逐级关队列（让数据流排空），最后释放资源。顺序乱了会导致线程访问已释放的对象（崩溃）。

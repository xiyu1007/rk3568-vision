# 03 — 采集（V4L2 零拷贝 + mp4 解码）

本篇讲 `src/camera_source.cpp`，这是「零拷贝」的核心，**面试必考**。

---

## 3.1 整体结构

CameraSource 一个类统一两种输入，由配置 `source` 决定走哪条路：

```cpp
bool CameraSource::Initialize(const CaptureConfig& config) {
    config_ = config;
    is_mp4_source_ = (config_.source == "mp4");   // 判断采集源
    return is_mp4_source_ ? InitializeMp4() : InitializeV4l2();
}
```

**逐行讲解**：`source == "mp4"` 就走 mp4 解码，否则走 V4L2 摄像头。这是"策略模式"——两种采集策略，接口统一。

## 3.2 V4L2 采集（InitializeV4l2）

### 3.2.1 打开设备 + 查能力

```cpp
bool CameraSource::InitializeV4l2() {
    // 1. 打开设备（非阻塞，配合 poll）
    video_fd_ = ::open(config_.device.c_str(), O_RDWR | O_NONBLOCK);
    if (video_fd_ < 0) { ... return false; }

    // 2. 查询能力，选择 buffer 类型（rkisp 是 Multiplanar）
    struct v4l2_capability capability{};
    Xioctl(video_fd_, VIDIOC_QUERYCAP, &capability);

    const uint32_t device_caps = (capability.capabilities & V4L2_CAP_DEVICE_CAPS)
                                     ? capability.device_caps
                                     : capability.capabilities;
    if (config_.use_multi_planar && (device_caps & V4L2_CAP_VIDEO_CAPTURE_MPLANE)) {
        buffer_type_ = V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE;   // 多平面
    } else if (device_caps & V4L2_CAP_VIDEO_CAPTURE) {
        buffer_type_ = V4L2_BUF_TYPE_VIDEO_CAPTURE;          // 单平面
    } else { ... return false; }
```

**逐行讲解**：
- `::open(dev, O_RDWR | O_NONBLOCK)`：`O_NONBLOCK` 非阻塞打开，配合 poll。否则 `DQBUF` 没数据时会阻塞，采集线程就无法响应退出。
- `VIDIOC_QUERYCAP`：查询设备能力。
- `V4L2_CAP_DEVICE_CAPS`：新版内核用 `device_caps` 字段（更准确），旧版用 `capabilities`。这里做了兼容判断。
- **多平面（MPLANE）**：rkisp 用 `V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE`（一个 buffer 多个平面）。为什么重要？rkisp 的 NV12 是 Y 和 UV 两个平面，但实际用单 plane（Y+UV 连续），代码里有处理。

### 3.2.2 Xioctl 封装

```cpp
int Xioctl(int fd, unsigned long request, void* arg) {
    int result;
    do {
        result = ::ioctl(fd, request, arg);
    } while (result == -1 && errno == EINTR);   // 被信号打断则重试
    return result;
}
```

**逐行讲解**：`ioctl` 可能被信号打断返回 `EINTR`，这里用 `do-while` 重试。这是系统调用封装的标准写法。

### 3.2.3 设置格式 + 帧率

```cpp
// 3. 设置格式 NV12
struct v4l2_format format{};
format.type = buffer_type_;
if (buffer_type_ == MPLANE) {
    format.fmt.pix_mp.width       = config_.width;
    format.fmt.pix_mp.height      = config_.height;
    format.fmt.pix_mp.pixelformat = V4L2_PIX_FMT_NV12;
    format.fmt.pix_mp.field       = V4L2_FIELD_ANY;
} else { ... }
Xioctl(video_fd_, VIDIOC_S_FMT, &format);

// 读回实际生效的宽高和 stride
width_     = format.fmt.pix_mp.width;
height_    = format.fmt.pix_mp.height;
stride_    = format.fmt.pix_mp.plane_fmt[0].bytesperline;   // 行跨度

// 4. 设置帧率
struct v4l2_streamparm parameter{};
parameter.parm.capture.timeperframe.numerator   = 1;
parameter.parm.capture.timeperframe.denominator = config_.fps;   // 1/25 秒每帧
Xioctl(video_fd_, VIDIOC_S_PARM, &parameter);
```

**逐行讲解**：
- `VIDIOC_S_FMT`：设置像素格式（NV12）和分辨率。**注意**：驱动可能不支持你请求的分辨率，会返回一个"最接近"的实际值，所以 S_FMT 后要**读回**实际生效的 width/height。
- `bytesperline`：每行字节数（行跨度）。**可能 > width**（硬件对齐要求），这就是 `stride_` 和 `width_` 分开存的原因。
- `VIDIOC_S_PARM`：设置帧率。`timeperframe = 1/25` 表示每帧 1/25 秒 = 25fps。

### 3.2.4 RequestV4l2Buffers（申请 + mmap + EXPBUF，零拷贝核心）

```cpp
bool CameraSource::RequestV4l2Buffers() {
    struct v4l2_requestbuffers request{};
    request.count  = config_.buffer_count;    // 申请 6 个 buffer
    request.type   = buffer_type_;
    request.memory = V4L2_MEMORY_MMAP;        // mmap 内存映射
    Xioctl(video_fd_, VIDIOC_REQBUFS, &request);
    buffer_count_ = request.count;

    mapped_buffers_.resize(buffer_count_);
    dma_fds_.assign(buffer_count_, -1);       // -1 表示未导出

    for (uint32_t i = 0; i < buffer_count_; ++i) {
        struct v4l2_buffer buffer{};
        buffer.type   = buffer_type_;
        buffer.memory = V4L2_MEMORY_MMAP;
        buffer.index  = i;
        Xioctl(video_fd_, VIDIOC_QUERYBUF, &buffer);   // 查 buffer 的 offset/length

        const size_t length = planes[0].length;
        const off_t  offset = planes[0].m.mem_offset;

        // mmap：把内核 DMA buffer 映射到用户空间
        void* address = ::mmap(nullptr, length, PROT_READ|PROT_WRITE, MAP_SHARED, video_fd_, offset);
        if (address == MAP_FAILED) { ... return false; }
        mapped_buffers_[i] = {address, length};

        // EXPBUF：导出 DMA-BUF fd（零拷贝给 RGA 用）
        struct v4l2_exportbuffer export_buffer{};
        export_buffer.type  = buffer_type_;
        export_buffer.index = i;
        export_buffer.plane = 0;
        Xioctl(video_fd_, VIDIOC_EXPBUF, &export_buffer);
        dma_fds_[i] = export_buffer.fd;
    }

    // 所有 buffer 初始入队（QBUF），使后续 DQBUF 能取出
    for (uint32_t i = 0; i < buffer_count_; ++i) {
        ... VIDIOC_QBUF ...
    }
    return true;
}
```

**逐行讲解（零拷贝的核心，逐点理解）**：
- `VIDIOC_REQBUFS`：向内核申请 N 个 buffer（这里是 6 个）。
- `VIDIOC_QUERYBUF`：查每个 buffer 的 `offset`（在内核 buffer 文件里的偏移）和 `length`（大小）。
- **`mmap(..., MAP_SHARED, video_fd_, offset)`**：把内核 DMA buffer 映射到用户空间。`MAP_SHARED` 表示共享映射（内核写、用户读同一块物理内存）。这是**零拷贝的关键**——用户直接读这块映射内存，数据不经过 CPU memcpy。
- **`VIDIOC_EXPBUF`**：把 buffer 导出成 DMA-BUF fd。这个 fd 可以传给 RGA/MPP，让它们**直接访问同一块物理内存**，跨设备零拷贝。
- `dma_fds_.assign(buffer_count_, -1)`：初始化为 -1，避免 `close(0)` 误关 stdin（0 是 stdin 的 fd）。
- **QBUF 初始入队**：V4L2 的 buffer 要先全部 QBUF（入队给内核），之后 DQBUF 才能取到。

**面试点**：零拷贝的完整链路是 `mmap（映射）+ EXPBUF（导出 fd）+ DMA-BUF（跨设备共享）`。mmap 让用户空间直接访问，EXPBUF 让 RGA/MPP 也能访问同一块内存，全程 CPU 不拷贝。

### 3.2.5 Start（STREAMON + 启动采集线程）

```cpp
bool CameraSource::Start() {
    // V4L2：STREAMON 开启数据流
    int buffer_type = (int)buffer_type_;
    if (Xioctl(video_fd_, VIDIOC_STREAMON, &buffer_type) < 0) { ... return false; }
    stream_started_ = true;
    running_.store(true);
    capture_thread_ = std::thread(&CameraSource::CaptureLoopV4l2, this);
    return true;
}
```

**逐行讲解**：`VIDIOC_STREAMON` 开启数据流（摄像头开始往 buffer 写数据），然后启动采集线程。`running_` 原子标志控制循环。

### 3.2.6 CaptureLoopV4l2（采集循环）

```cpp
void CameraSource::CaptureLoopV4l2() {
    while (running_.load()) {
        // 1. poll 限时等待 buffer 就绪
        struct pollfd poll_fd{video_fd_, POLLIN, 0};
        if (::poll(&poll_fd, 1, kPollTimeoutMs) <= 0) continue;   // 超时则继续循环（检查退出标志）

        // 2. DQBUF 取出 buffer
        struct v4l2_buffer buffer{};
        buffer.type   = buffer_type_;
        buffer.memory = V4L2_MEMORY_MMAP;
        if (Xioctl(video_fd_, VIDIOC_DQBUF, &buffer) < 0) { ... continue; }

        // 3. 构造零拷贝帧（引用 mmap 地址，不拷贝）
        const uint32_t buffer_index = buffer.index;
        const MappedBuffer& mapped = mapped_buffers_[buffer_index];

        FramePtr frame(new Frame, [this, buffer_index](Frame* raw) {
            delete raw;
            ReturnBuffer(buffer_index);      // 引用归零时 QBUF 归还
        });
        frame->sequence          = buffer.sequence;
        frame->width             = width_;
        frame->height            = height_;
        frame->capture_timestamp = GetCurrentTimestampUs();
        frame->nv12_data         = (const uint8_t*)mapped.address;   // 指向 mmap 映射地址
        frame->nv12_stride       = stride_;
        frame->dma_fds.push_back(dma_fds_[buffer_index]);
        frame->buffer_index      = buffer_index;

        // 4. 回调通知上层（回调里只入队）
        InvokeCallback(std::move(frame));
    }
}
```

**逐行讲解（每一行都重要）**：
- `poll(&poll_fd, 1, kPollTimeoutMs)`：限时等待 buffer 就绪（POLLIN 表示有数据可读）。超时 `continue`，**让循环周期性检查 `running_` 退出标志**（否则优雅退出时采集线程退不出来）。
- `VIDIOC_DQBUF`：从内核取一个填好数据的 buffer。
- **`FramePtr frame(new Frame, [this, buffer_index](Frame* raw){ ... })`**：这是零拷贝 + 生命周期管理的精髓：
  - `new Frame` 分配 Frame 对象；
  - 第二个参数是 **lambda 自定义 deleter**：当这个 Frame 的 shared_ptr 引用计数归零时，自动调 `delete raw` + `ReturnBuffer(buffer_index)`。
  - `ReturnBuffer` 就是 QBUF 把 buffer 归还给内核，让内核继续往这个 buffer 写下一帧。
- `frame->nv12_data = mapped.address`：**不拷贝数据**，直接指向 mmap 映射的 DMA buffer 虚拟地址。
- `frame->dma_fds.push_back(dma_fds_[buffer_index])`：把 EXPBUF 导出的 fd 放进帧，供 RGA 零拷贝消费。
- `InvokeCallback(std::move(frame))`：回调分发（内部加锁调注册的回调），回调里只入队。

**面试点（必答）**：
1. **零拷贝在哪**：`nv12_data` 直接指向 mmap 映射地址，DQBUF 后不 memcpy。
2. **buffer 怎么归还**：shared_ptr 自定义 deleter，引用归零时 QBUF。
3. **为什么 poll 超时**：让采集线程能周期性检查退出标志，实现优雅退出。

### 3.2.7 ReturnBuffer（QBUF 归还）

```cpp
void CameraSource::ReturnBuffer(uint32_t buffer_index) {
    std::lock_guard<std::mutex> lock(buffer_mutex_);   // 保护 QBUF ioctl
    if (!running_.load() || !stream_started_) return;  // 已停止则无需归还
    ... VIDIOC_QBUF ...   // 把 buffer 归还给内核
}
```

**逐行讲解**：QBUF 归还 buffer。加锁保护（可能被下游线程并发调用），`!running_ || !stream_started_` 时跳过（已经停流，归还没意义）。

## 3.3 mp4 解码（InitializeMp4 + CaptureLoopMp4）

### 3.3.1 InitializeMp4

```cpp
bool CameraSource::InitializeMp4() {
    avformat_open_input(&format_context_, config_.file.c_str(), nullptr, nullptr);
    avformat_find_stream_info(format_context_, nullptr);
    video_stream_index_ = av_find_best_stream(format_context_, AVMEDIA_TYPE_VIDEO, -1, -1, nullptr, 0);

    codec_ = avcodec_find_decoder(video_stream->codecpar->codec_id);
    codec_context_ = avcodec_alloc_context3(codec_);
    avcodec_parameters_to_context(codec_context_, video_stream->codecpar);
    avcodec_open2(codec_context_, codec_, nullptr);

    width_  = codec_context_->width;     // 用 mp4 文件本身的分辨率
    height_ = codec_context_->height;
    // 帧率也用文件本身的
    const AVRational fr = video_stream->avg_frame_rate;
    frame_rate_ = (uint32_t)(av_q2d(fr) + 0.5);   // 分数转小数再四舍五入

    // sws_scale 把解码帧转 NV12
    nv12_frame_ = av_frame_alloc();
    nv12_frame_->format = AV_PIX_FMT_NV12;
    nv12_frame_->width  = width_;
    nv12_frame_->height = height_;
    av_frame_get_buffer(nv12_frame_, 32);
    sws_context_ = sws_getContext(width_, height_, codec_context_->pix_fmt,
                                  width_, height_, AV_PIX_FMT_NV12, SWS_FAST_BILINEAR, ...);
}
```

**逐行讲解**：
- FFmpeg 解码标准流程：`open_input → find_stream_info → find_best_stream → find_decoder → open2`。
- `width_/height_` 用**文件本身的分辨率**（`codec_context_->width`），不读配置（mp4 输入时配置的宽高被忽略）。
- `av_q2d(fr)`：把 AVRational 分数（如 30/1）转 double（30.0），`+0.5` 四舍五入。
- `sws_getContext`：创建 sws_scale 的转换上下文，把 mp4 解码出的像素格式（pix_fmt）转成 NV12。

### 3.3.2 CaptureLoopMp4（解码循环，按源帧率节拍）

```cpp
void CameraSource::CaptureLoopMp4() {
    while (running_.load()) {
        // 节拍：保持与源视频一致帧率
        const uint64_t target_us = start_time_us_ + frame_index_ * frame_interval_us_;
        const uint64_t now_us = GetCurrentTimestampUs();
        if (now_us < target_us) {
            sleep_for(microseconds(target_us - now_us));   // 睡到目标时刻
        }

        int result = av_read_frame(format_context_, packet_);   // 读一帧
        if (result == AVERROR_EOF) {
            av_seek_frame(format_context_, video_stream_index_, 0, AVSEEK_FLAG_BACKWARD);  // 循环播放
            avcodec_flush_buffers(codec_context_);
            continue;
        }
        if (packet_->stream_index != video_stream_index_) { av_packet_unref(packet_); continue; }

        avcodec_send_packet(codec_context_, packet_);
        av_packet_unref(packet_);
        avcodec_receive_frame(codec_context_, decoded_frame_);

        // sws_scale 转 NV12
        sws_scale(sws_context_, decoded_frame_->data, decoded_frame_->linesize,
                  0, codec_context_->height, nv12_frame_->data, nv12_frame_->linesize);

        // 拷贝到 CPU 内存（mp4 输入无 DMA）
        auto nv12_cpu = std::make_shared<std::vector<uint8_t>>(width_ * height_ * 3 / 2);
        memcpy(...);
        frame->nv12_data = nv12_cpu->data();
        frame->nv12_cpu  = std::move(nv12_cpu);
        ++frame_index_;
        InvokeCallback(std::move(frame));
    }
}
```

**逐行讲解**：
- **节拍控制**：`target_us = start + index * interval`，睡到目标时刻再读下一帧，让 mp4 以源帧率播放（不是狂读）。
- `av_read_frame` 读一帧（可能是音频或视频），只处理视频流。
- `AVERROR_EOF`：播完 seek 回开头 + flush 解码器，实现**循环播放**。
- `sws_scale`：解码帧转 NV12。
- mp4 输入**无 DMA**，所以数据拷到 `nv12_cpu`（CPU 内存的 vector），frame 引用它（和 V4L2 的零拷贝形成对比）。

**面试点**：mp4 输入有拷贝（sws_scale + memcpy），V4L2 输入零拷贝（mmap 引用）。为什么 mp4 要拷贝？因为 mp4 解码出来的是 FFmpeg 的内存，不涉及内核 DMA buffer，而且 sws_scale 本身要格式转换。

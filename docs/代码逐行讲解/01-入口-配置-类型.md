## 1.1 `src/main.cpp` — 程序入口

main.cpp 只做三件事：**注册信号处理 → 解析命令行 + 加载配置 → 创建并跑流水线**。它不碰业务逻辑。

### 1.1.1 信号处理

```cpp
namespace {
std::atomic<bool> g_stop{false};     // 全局停止标志

void SignalHandler(int signal) {
    (void)signal;                     // 不用 signal 参数，避免编译器警告
    g_stop.store(true);               // 原子写停止标志
}
}
```

**逐行讲解**：
- `std::atomic<bool> g_stop{false}`：一个全局的原子布尔标志。用 `atomic` 是因为**信号处理函数和主循环在不同的执行上下文里并发访问**这个变量，普通 `bool` 会有数据竞争（data race），是未定义行为。`atomic` 保证读写的原子性。
- `(void)signal;`：把参数显式"使用"掉，避免 `-Wall -Wextra` 的 unused parameter 警告。
- `g_stop.store(true)`：原子写。信号处理函数里**不能做重活**（比如调 printf、加锁、malloc 都可能不安全，因为信号可能打断任意代码），所以只设置一个标志就返回，让主循环去处理退出。

### 1.1.2 main 函数开头

```cpp
int main(int argc, char* argv[]) {
    std::signal(SIGINT, SignalHandler);   // Ctrl+C
    std::signal(SIGTERM, SignalHandler);  // kill 默认信号
    std::signal(SIGPIPE, SIG_IGN);        // 忽略 SIGPIPE
```

**逐行讲解**：
- `std::signal(SIGINT, SignalHandler)`：注册 SIGINT（键盘 Ctrl+C）的处理函数。
- `std::signal(SIGTERM, SignalHandler)`：SIGTERM 是 `kill <pid>` 默认发送的终止信号。
- `std::signal(SIGPIPE, SIG_IGN)`：**这是关键的一行**。SIGPIPE 的触发场景：向一个**已经被对端关闭的 socket/管道**写数据时，内核会发 SIGPIPE，而 SIGPIPE 的默认动作是**直接终止进程**。本项目推流用 RTMP（底层是 TCP socket），如果 mediamtx 突然断开，`write` 就会触发 SIGPIPE 把进程杀掉。这里 `SIG_IGN` 忽略它，让 `write` 返回 `-1` + `errno=EPIPE`，由推流代码自己处理（断线重连）。

**面试点**：SIGPIPE 的默认行为是什么？为什么网络程序要忽略它？

### 1.1.3 命令行解析（getopt_long）

```cpp
static const option kLongOptions[] = {
    {"config",       required_argument, nullptr, 'c'},
    {"device",       required_argument, nullptr, 'd'},
    {"width",        required_argument, nullptr, 'W'},
    {"height",       required_argument, nullptr, 'H'},
    {"fps",          required_argument, nullptr, 'f'},
    {"stream",       required_argument, nullptr, 's'},
    {"no-stream",    no_argument,       nullptr, 1000},   // 无短选项，用纯数字 1000 标识
    {"no-inference", no_argument,       nullptr, 1001},
    {"record",       required_argument, nullptr, 1002},
    {"verbose",      no_argument,       nullptr, 'v'},
    {"help",         no_argument,       nullptr, 'h'},
    {nullptr, 0, nullptr, 0},                              // 结束哨兵
};

int option;
while ((option = getopt_long(argc, argv, "c:d:W:H:f:s:vh",
                             kLongOptions, nullptr)) != -1) {
    switch (option) {
        case 'c':   config_path = optarg; break;
        ...
        case 1000:  no_stream = true; break;
        ...
    }
}
```

**逐行讲解**：
- `struct option` 数组每个元素 4 个字段：`{长选项名, 是否需要参数, 标志, 短选项值}`。
  - `required_argument`：这个选项后面必须跟参数（如 `-c conf/default.yaml`）。
  - `no_argument`：开关型选项，没有参数（如 `--no-stream`）。
  - 第 4 个字段是「返回值」：如果有对应短选项（如 `'c'`），getopt_long 返回 `'c'`；如果没有短选项（如 `--no-stream`），用一个**纯数字**（1000、1001、1002）区分。
- `{nullptr, 0, nullptr, 0}` 是结束哨兵，getopt_long 靠它知道数组结束了。
- `"c:d:W:H:f:s:vh"` 是短选项串，**冒号 `:` 表示该短选项需要参数**（如 `-c 需要参数`，`-v` 不需要）。
- `optarg` 是全局变量，指向当前选项的参数值。
- `std::atoi(optarg)`：把字符串参数转整数（width/height/fps）。

**面试点**：getopt_long 的 `required_argument`、`no_argument` 区别；`optarg` 是什么。

### 1.1.4 配置加载 + 命令行覆盖

```cpp
vision::Config config;
vision::LoadConfigFromFile(config_path, config);   // 先读 YAML 文件

if (!device.empty())      { config.capture.device = device; }              // 命令行覆盖
if (width > 0)            { config.capture.width  = (uint32_t)width; }
if (height > 0)           { config.capture.height = (uint32_t)height; }
if (fps > 0)              { config.capture.fps    = (uint32_t)fps; }
if (!stream_url.empty())  { config.stream.url = stream_url; config.stream.enabled = true; }
if (no_stream)            { config.stream.enabled = false; }
if (no_inference)         { config.inference.enabled = false; }
if (!record_path.empty()) { config.record.path = record_path; config.record.enabled = true; }
if (verbose)              { config.log.level = "debug"; }
```

**逐行讲解**：
- 先 `LoadConfigFromFile` 加载 YAML 默认配置，**再用命令行覆盖**——命令行优先级高于配置文件。这是典型的"配置分层"设计（默认值 < 配置文件 < 命令行）。
- 每个 `if` 都在判断"命令行是否提供了这个选项"，提供了才覆盖。比如 `width > 0` 表示用户没传 `-W` 时 width 还是 0（初始值），就不覆盖。

### 1.1.5 流水线生命周期

```cpp
vision::Logger::instance().init(config.log);   // 初始化日志

vision::Pipeline pipeline(config);             // 构造（只是存配置）
if (!pipeline.Initialize()) {                  // 打开采集/推理/编码
    ... return 1;
}
if (!pipeline.Start()) {                       // 启动所有线程
    ... return 1;
}

while (!g_stop.load()) {                       // 主循环轮询停止标志
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
}

pipeline.Stop();                               // 优雅退出
vision::Logger::instance().shutdown();
return 0;
```

**逐行讲解**：
- 生命周期分四步：**构造（存配置）→ Initialize（打开资源）→ Start（起线程）→ Stop（收线程）**。这是 RAII + 显式生命周期的经典写法。
- `while (!g_stop.load())`：主循环不干活，就轮询停止标志。用 `sleep 200ms` 避免忙轮询（busy loop 空转占满 CPU）。
- 收到 SIGINT/SIGTERM 后，`g_stop` 被信号处理函数置 true，主循环退出，调 `pipeline.Stop()` 优雅收尾。

## 1.2 `include/vision/config.hpp` — 配置结构体

config.hpp 定义所有配置结构体，和 `conf/default.yaml` 一一对应。

```cpp
struct CaptureConfig {
    std::string source = "v4l2";          // 采集源：v4l2 / mp4
    std::string device = "/dev/video0";   // V4L2 设备节点
    std::string file = "data/test.mp4";   // mp4 文件路径
    uint32_t width = 1280;                // 采集宽
    uint32_t height = 720;                // 采集高
    uint32_t fps = 25;                    // 帧率
    uint32_t buffer_count = 6;            // V4L2 DMA buffer 数量
    bool use_multi_planar = true;         // 是否用多平面 API
};

struct InferenceConfig {
    bool enabled = true;
    std::string model_path = "model/yolov5n.rknn";
    std::string labels_path = "model/coco_80_labels_list.txt";
    float confidence_threshold = 0.25f;   // 置信度阈值
    float nms_threshold = 0.45f;          // NMS IoU 阈值
    uint32_t model_width = 640;
    uint32_t model_height = 640;
    uint32_t npu_core = 0;                // NPU 核心（RK3568 固定 0）
    bool use_sigmoid = false;             // 后处理是否 sigmoid
};

struct EncodeConfig {
    bool hardware = true;                 // true=MPP 硬编 / false=libx264 软编
    uint32_t bitrate = 4000000;
    uint32_t gop_size = 50;
    std::string preset = "fast";
    std::string profile = "high";
};

struct StreamConfig {
    bool enabled = true;
    std::string url = "rtmp://127.0.0.1:1935/live/stream";
    bool reconnect = true;
    uint32_t reconnect_delay_ms = 2000;
    int32_t max_reconnect = -1;           // -1 无限重连
};
```

**逐行讲解（几个关键点）**：
- 每个结构体用**成员初始化器（默认值）**（`= "v4l2"` 这种），这是 C++11 的 in-class member initializer。好处：即使 YAML 里没写某个字段，也有合理默认值。
- `use_sigmoid`：后处理是否再 sigmoid。**标准 yolov5s 输出是 logits（要 sigmoid），yolov5n/relu 版输出已是 sigmoid 后值（不要再 sigmoid）**。这个配置和模型强相关，换模型必须同步改。
- `gop_size`（关键帧间隔）：值太大拉流端迟迟等不到 IDR 出不了画面，太小码率高。默认 50 帧 = 2 秒。
- `max_reconnect = -1`：-1 表示无限重连（推流断了永远重试）。

## 1.3 `src/config.cpp` — 自研 YAML 解析器

**核心思路**：把 YAML 的**缩进层级**拍平成 `"section.key" -> "value"` 的扁平 map，零第三方依赖（不引 yaml-cpp）。

### 1.3.1 ParseYaml 主函数

```cpp
std::map<std::string, std::string> ParseYaml(const std::string& path) {
    std::map<std::string, std::string> key_values;
    std::ifstream file(path);
    if (!file.is_open()) return key_values;   // 打不开返回空 map

    std::string line;
    std::string section;
    while (std::getline(file, line)) {
        // 去掉行尾注释（'#' 开头到行尾）
        const size_t comment_pos = line.find('#');
        if (comment_pos != std::string::npos) {
            line = line.substr(0, comment_pos);
        }

        const std::string trimmed = TrimWhitespace(line);
        if (trimmed.empty()) continue;         // 空行跳过

        const size_t colon_pos = trimmed.find(':');
        if (colon_pos == std::string::npos) continue;   // 没有冒号的行跳过

        const std::string key   = TrimWhitespace(trimmed.substr(0, colon_pos));
        const std::string value = RemoveQuotes(TrimWhitespace(trimmed.substr(colon_pos + 1)));
        const bool has_indent = (line[0] == ' ' || line[0] == '\t');

        if (value.empty()) {
            if (!has_indent) section = key;    // 无缩进且值为空 → 这是 section 头
        } else {
            if (has_indent && !section.empty()) {
                key_values[section + "." + key] = value;   // "section.key" -> value
            } else {
                key_values[key] = value;                   // 顶层键
            }
        }
    }
    return key_values;
}
```

**逐行讲解**：
- `std::ifstream file(path)`：打开文件，`is_open()` 判断成功。
- `std::getline(file, line)`：逐行读，返回 false 表示读完。
- 注释处理：`line.find('#')` 找第一个 `#`，`substr(0, comment_pos)` 截断掉 `#` 及之后。注意这里是**行内注释**（`key: value # 注释`）。
- `TrimWhitespace`：去掉首尾空白（空格、tab、回车）。
- `find(':')`：找键值分隔符。`substr(0, colon_pos)` 是键，`substr(colon_pos+1)` 是值。
- `RemoveQuotes`：去掉值的引号（单引号或双引号）。
- `has_indent = (line[0] == ' ' || line[0] == '\t')`：**用行首是否有缩进**判断层级。这是关键技巧——YAML 里 `capture:` 是顶格（section 头），`source: v4l2` 有缩进（属于 capture 的键值）。
- `if (value.empty())`：值空说明这行是 `capture:` 这种 section 头，记下 `section`。
- 拼 key：`section + "." + key`，比如 `capture.source`。

**面试点**：这是极简 YAML，只支持两层 `key: value` 扁平结构，不支持数组、锚点、多级嵌套。够本项目用。如果被问"为什么不用 yaml-cpp"，答"为了零第三方依赖、部署简单"。

### 1.3.2 TryGetValue 类型转换

```cpp
template <typename T>
void TryGetValue(const std::map<std::string, std::string>& key_values,
                 const std::string& key, T& out) {
    const auto it = key_values.find(key);
    if (it == key_values.end()) return;          // key 不存在，保留默认值

    if constexpr (std::is_same_v<T, std::string>) {
        out = it->second;
    } else if constexpr (std::is_same_v<T, bool>) {
        out = (it->second == "true" || it->second == "1" || it->second == "yes");
    } else {
        std::istringstream stream(it->second);   // 数值：用 istringstream 转
        stream >> out;
    }
}
```

**逐行讲解**：
- `key_values.find(key)`：找 key，找不到就 return（`out` 保持默认值）。
- `if constexpr (std::is_same_v<T, std::string>)`：**编译期 if**。C++17 特性，`if constexpr` 在编译时决定走哪个分支，不匹配的分支**不编译**。这样同一个模板能处理 string/bool/数值三种类型。
- `std::is_same_v<T, bool>`：类型 trait，判断 T 是不是 bool。
- `std::istringstream >> out`：字符串流解析数值（"1280" → 1280），利用了 C++ 的流提取运算符自动做类型转换。

**面试点**：`if constexpr` 和普通 `if` 的区别——普通 `if` 两个分支都要编译，`if constexpr` 只编译匹配的分支，所以可以对不同类型写不同的、不兼容的代码。

### 1.3.3 LoadConfigFromFile

```cpp

        return false;
    }

    TryGetValue(key_values, "capture.width",  config.capture.width);

```

**逐行讲解**：把 map 里的每个 `section.key` 用 `TryGetValue` 填进 `Config` 对应字段。字段很多，就一行一个，清晰直白。

## 1.4 `include/vision/types.hpp` — 核心类型

### 1.4.1 Frame（最重要的类型）

```cpp
struct Frame {
    uint64_t sequence;                // 帧序号（单调递增）
    uint32_t width, height;           // 宽高
    TimestampUs capture_timestamp;    // 采集完成时间戳（单调时钟微秒）
    TimestampUs inference_timestamp;  // 推理完成时间戳

    const uint8_t* nv12_data;         // NV12 Y 平面起始地址
    uint32_t nv12_stride;             // 行跨度 bytesperline（可能 != width）

    std::vector<int> dma_fds;         // dmabuf fd（V4L2 零拷贝来源）
    uint32_t buffer_index;            // V4L2 buffer index（QBUF 归还用）
    std::shared_ptr<std::vector<uint8_t>> nv12_cpu;  // CPU 内存（mp4 来源）

    DetectResult detection;           // 检测结果
};
using FramePtr = std::shared_ptr<Frame>;
```

**逐行讲解（Frame 的双来源设计，面试重点）**：
- 一帧 NV12 数据有两种来源：
  1. **V4L2 摄像头（零拷贝）**：`nv12_data` 指向 mmap 映射的 DMA buffer 虚拟地址；`dma_fds` 存 EXPBUF 导出的 fd（给 RGA 用）；`buffer_index` 记录是第几个 buffer，供 QBUF 归还。buffer 的归还靠 `shared_ptr` 自定义 deleter（引用归零时 QBUF）。
  2. **mp4 文件**：FFmpeg 解码到 CPU 内存，`nv12_data` 指向 `nv12_cpu` 持有的 vector。
- 下游（推理/编码）**不关心数据从哪来**，统一用 `nv12_data` 访问。这是"面向接口"的设计。
- `nv12_stride`（行跨度）可能 > width，因为硬件对每行字节数有对齐要求（bytesperline）。
- `FramePtr = std::shared_ptr<Frame>`：帧用 shared_ptr 管理，因为一个 Frame 会被多个队列/线程"看到"（引用计数自动管理生命周期）。

### 1.4.2 PacketPtr（编码包）

```cpp
struct PacketDeleter {
    void operator()(AVPacket* packet) const {
        if (packet != nullptr) av_packet_free(&packet);   // 调 FFmpeg 释放
    }
};
using PacketPtr = std::shared_ptr<AVPacket>;
inline PacketPtr CreatePacket() {
    return PacketPtr(av_packet_alloc(), PacketDeleter{});
}
```

**逐行讲解**：
- `PacketDeleter::operator()(AVPacket*)`：函数对象（functor），作为 shared_ptr 的自定义 deleter，调 `av_packet_free` 释放 FFmpeg 的 AVPacket。
- `CreatePacket()`：`av_packet_alloc()` 分配一个 AVPacket，包装进 shared_ptr。这样 AVPacket 这个 C 库的裸指针，就有了 RAII 管理——离开作用域自动释放，不用手动 `av_packet_free`。

**面试点**：这是"C++ 用 shared_ptr 自定义 deleter 管理 C 库资源"的经典模式。AVPacket 不是 C++ 对象（没有析构函数），所以要自定义 deleter 调 `av_packet_free`。

### 1.4.3 GetCurrentTimestampUs（单调时钟）

```cpp
using TimestampUs = uint64_t;
inline TimestampUs GetCurrentTimestampUs() {
    struct timespec ts{};
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (uint64_t)ts.tv_sec * 1000000ULL + (uint64_t)ts.tv_nsec / 1000ULL;
}
```

**逐行讲解**：
- `clock_gettime(CLOCK_MONOTONIC, &ts)`：取单调时钟。`CLOCK_MONOTONIC` 从开机起单调递增，**不受系统时间调整影响**（NTP 校时、手动改时间都不会让它跳变）。
- `tv_sec * 1000000 + tv_nsec / 1000`：秒转微秒 + 纳秒转微秒，拼成微秒时间戳。

**面试点**：测延迟/性能统计为什么用 CLOCK_MONOTONIC 而不用 CLOCK_REALTIME？因为 REALTIME 是墙钟，改时间会跳变，测出来的延迟会错。

### 1.4.4 DetectBox / DetectResult（检测结果）

```cpp
constexpr int kMaxBoxes = 64;        // 单帧最多 64 个框
struct DetectBox {
    int x, y;                         // 左上角
    int width, height;                // 宽高
    int class_id;                     // 类别 ID
    float confidence;                 // 置信度
    char label[kMaxLabelLength];      // 类别标签文本
};
struct DetectResult {
    uint32_t count;                   // 框数量
    DetectBox boxes[kMaxBoxes];       // 框数组（定长，避免动态分配）
};
```

**逐行讲解**：
- `kMaxBoxes = 64`：单帧最多 64 个框，`boxes` 是定长数组（不是 vector），**避免每帧动态分配内存**（推理线程高频调用，省去 malloc 开销）。
- `label[kMaxLabelLength]`：定长字符数组存标签名（如 "person"）。

## 1.5 `include/vision/debug.hpp` — DEBUG 条件编译宏

### 1.5.1 ScopedProfiler（RAII 作用域计时器）

```cpp
class ScopedProfiler {
public:
    explicit ScopedProfiler(const char* name)
        : name_(name), start_us_(GetCurrentTimestampUs()) {}   // 构造时记时间戳

    ~ScopedProfiler() {
        const TimestampUs elapsed_us = GetCurrentTimestampUs() - start_us_;
        Logger::instance().debug("[profile] %s took %llu us", name_, ...);
    }
    ScopedProfiler(const ScopedProfiler&) = delete;   // 禁止拷贝
    ...
private:
    const char* name_;
    TimestampUs start_us_;
};
```

**逐行讲解**：
- **RAII 计时器**：构造时记录起始时间，**析构时打印耗时**。所以只要在函数开头声明一个 `ScopedProfiler`，函数退出时（无论正常 return 还是异常）都会自动打印这段代码的耗时。
- `= delete`：禁止拷贝构造和拷贝赋值，因为计时器拷贝没有意义。
- 这是"用对象生命周期做资源管理"的典型 RAII 应用。

### 1.5.2 条件编译宏

```cpp
#ifdef VISION_DEBUG
#define VISION_DEBUG_LOG(...) vision::Logger::instance().debug(__VA_ARGS__)
#define VISION_PROFILE_SCOPE(name) \
    vision::ScopedProfiler _vision_profiler_##__LINE__(name)
#else
#define VISION_DEBUG_LOG(...) ((void)0)
#define VISION_PROFILE_SCOPE(name) ((void)0)

```

**逐行讲解**：
- `#ifdef VISION_DEBUG`：VISION_DEBUG 是 Makefile 里 `make debug` 定义的宏（`-DVISION_DEBUG`）。
- **DEBUG 构建**：`VISION_DEBUG_LOG(...)` 展开成真正的日志调用；`VISION_PROFILE_SCOPE(name)` 展开成声明一个 ScopedProfiler 对象。
  - `##__LINE__`：宏里的**记号粘贴**，把 `_vision_profiler_` 和行号拼成一个唯一变量名（避免同一作用域声明两个同名变量冲突）。
  - `__VA_ARGS__`：可变参数宏，把 `...` 原样展开。
- **RELEASE 构建**：宏展开成 `((void)0)`（空语句），调试代码**编译期被优化掉，零运行时开销**。

**面试点**：`##`（记号粘贴）和 `__VA_ARGS__`（可变参数）是预处理器的两个常用技巧；条件编译让 release 构建零开销。

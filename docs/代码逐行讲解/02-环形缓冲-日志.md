## 2.1 `ring_buffer.hpp` — 有界环形缓冲（面试必考）

这是整个流水线解耦的关键，**面试几乎必问**。

### 2.1.1 成员变量

```cpp
template <typename T>
class RingBuffer {
private:
    size_t    capacity_;            // 容量（可容纳元素数）
    std::vector<T> buffer_;         // 环形存储区
    size_t    head_ = 0;            // 队首（读位置）
    size_t    tail_ = 0;            // 队尾（写位置）
    size_t    size_  = 0;           // 当前元素个数
    bool      closed_ = false;      // 关闭标志
    uint64_t  dropped_ = 0;         // 累计丢帧数

    mutable std::mutex      mutex_;        // 保护上述字段
    std::condition_variable not_empty_;    // 非空条件变量
};
```

**逐行讲解**：
- 用固定大小 `vector<T> buffer_(capacity)` + 头尾指针实现环形队列。**不动态扩容**，避免高负载下内存分配抖动。
- `head_` 是读位置（队首），`tail_` 是写位置（队尾），`size_` 是当前元素数。
- `closed_`：关闭标志，配合条件变量让消费者优雅退出。
- `dropped_`：累计丢弃的帧数（性能统计用）。
- `mutable mutex_`：`mutable` 让 const 成员函数（如 `Size()`、`Dropped()`）也能加锁。

### 2.1.2 Push（生产者入队，满则丢最旧）

```cpp
void Push(T item) {
    std::lock_guard<std::mutex> lock(mutex_);
    if (size_ == capacity_) {                 // 满了
        head_ = (head_ + 1) % capacity_;      // 丢弃最旧的（head 前移）
        --size_;
        ++dropped_;
    }
    buffer_[tail_] = std::move(item);         // 写入尾部
    tail_ = (tail_ + 1) % capacity_;          // 尾指针前移
    ++size_;
    not_empty_.notify_one();                  // 唤醒一个消费者
}
```

**逐行讲解**：
- `std::lock_guard`：RAII 锁，作用域结束自动解锁。
- `if (size_ == capacity_)`：队列满。此时**丢弃最旧的元素**——`head_` 前移一位（跳过最旧的），`size_` 减 1。这就是"丢最旧"策略。
- `head_ = (head_ + 1) % capacity_`：**取模实现环形回绕**，头指针走到末尾就绕回开头。
- `buffer_[tail_] = std::move(item)`：移动语义写入，避免拷贝。
- `not_empty_.notify_one()`：唤醒一个正在等待的消费者。

**面试点**：为什么丢最旧而不是丢最新？实时视频场景，**旧帧价值低**（画面要的是"最新"），宁可丢旧帧也不让延迟累积。如果丢最新（阻塞生产者），会导致延迟越来越大。

### 2.1.3 Pop（消费者阻塞取出）

```cpp
bool Pop(T& out) {
    std::unique_lock<std::mutex> lock(mutex_);
    not_empty_.wait(lock, [this] { return size_ > 0 || closed_; });
    if (size_ == 0) {
        return false;                          // 队列空且已关闭
    }
    out = std::move(buffer_[head_]);           // 取队首
    head_ = (head_ + 1) % capacity_;
    --size_;
    return true;
}
```

**逐行讲解**：
- `std::unique_lock`（不是 lock_guard）：因为条件变量的 `wait` 需要**解锁/重新加锁**的能力，`unique_lock` 支持手动 `lock/unlock`。
- `not_empty_.wait(lock, predicate)`：这是关键。它做了三件事：
  1. 检查谓词 `size_ > 0 || closed_`，为 false 则**原子地释放锁并阻塞**；
  2. 被 `notify_one/all` 唤醒；
  3. **重新加锁**，再次检查谓词（避免虚假唤醒）。
- 返回 false 表示"队列空且已关闭"，调用方据此退出循环（优雅退出）。
- `std::move(buffer_[head_])`：移动取出，避免拷贝。

**面试点**：`wait(lock, predicate)` 的谓词为什么必要？因为存在**虚假唤醒（spurious wakeup）**——线程可能被唤醒但条件并不满足，谓词保证唤醒后重新检查，不满足继续睡。

### 2.1.4 PopFor（带超时，稳帧器用）

```cpp
bool PopFor(T& out, std::chrono::milliseconds timeout) {
    std::unique_lock<std::mutex> lock(mutex_);
    if (!not_empty_.wait_for(lock, timeout,
                             [this] { return size_ > 0 || closed_; })) {
        return false;                          // 超时，无数据
    }
    if (size_ == 0) return false;
    out = std::move(buffer_[head_]);
    head_ = (head_ + 1) % capacity_;
    --size_;
    return true;
}
```

**逐行讲解**：`wait_for(lock, timeout, predicate)` 是带超时的 wait。稳帧器用它**按节拍等待**——最多等 `timeout` 毫秒，超时返回 false（没等到新帧，就补上一帧）。

### 2.1.5 Close（优雅退出）

```cpp
void Close() {
    std::lock_guard<std::mutex> lock(mutex_);
    closed_ = true;
    not_empty_.notify_all();                   // 唤醒所有阻塞的消费者
}
```

**逐行讲解**：置 `closed_` 并 `notify_all`。所有阻塞在 `Pop` 上的消费者被唤醒，谓词 `closed_` 为 true，`size_ == 0` 时返回 false，线程据此退出 `while` 循环。这是**优雅退出**的关键。

## 2.2 `logger` — 异步日志系统

### 2.2.1 单例（Meyers Singleton）

```cpp
Logger& Logger::instance() {
    static Logger inst;    // 局部静态对象，首次调用时构造
    return inst;
}
```

**逐行讲解**：函数内 static 对象，首次调用 `instance()` 时构造，之后每次返回同一个对象。**C++11 起局部 static 对象的初始化是线程安全的**（编译器自动加锁/原子保护）。这是最简单、最安全的单例写法。

**面试点**：为什么不用饿汉式（全局对象）？饿汉式程序启动就构造（可能浪费资源），且初始化顺序不确定（static initialization order fiasco）。Meyers 单例是懒汉式 + 线程安全，是最佳实践。

### 2.2.2 init（初始化 + 启动写线程）

```cpp
bool Logger::init(const LogConfig& cfg) {
    if (inited_) return true;          // 幂等

    if (cfg.level == "debug")      level_ = LogLevel::Debug;
    else if (cfg.level == "warn")  level_ = LogLevel::Warn;
    else if (cfg.level == "error") level_ = LogLevel::Error;
    else                           level_ = LogLevel::Info;

    ...
    std::filesystem::create_directories(path(file_).parent_path(), ec);  // 创建目录
    fp_ = std::fopen(file_.c_str(), "a");                               // 追加模式打开

    inited_ = true;
    if (async_) {
        running_.store(true);
        worker_ = std::thread(&Logger::workerLoop, this);   // 启动写线程
    }
    return true;
}
```

**逐行讲解**：
- `if (inited_) return true`：幂等，重复调用忽略。
- 字符串解析日志级别。
- `create_directories`：日志目录不存在先创建。
- `fopen(file_, "a")`：追加模式。
- `std::thread(&Logger::workerLoop, this)`：启动后台写线程，成员函数作为线程入口要传 `this`。

### 2.2.3 log（核心日志接口，生产者）

```cpp
void Logger::log(LogLevel level, const char* fmt, ...) {
    if ((int)level < (int)level_) return;     // 低于当前级别直接丢弃

    char body[kMaxLineLen];
    va_list ap;
    va_start(ap, fmt);
    std::vsnprintf(body, sizeof(body), fmt, ap);   // 格式化到缓冲
    va_end(ap);

    std::string line = "[" + formatNow() + "] [" + levelName(level) + "] " + body + "\n";

    if (async_) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            queue_.push_back(std::move(line));     // 只入队，不写 I/O
        }
        cv_.notify_one();
    } else {
        std::lock_guard<std::mutex> lock(file_mutex_);
        writeLine(line);                          // 同步直接写
    }
}
```

**逐行讲解**：
- `if ((int)level < (int)level_) return`：级别过滤，低于当前级别的日志直接丢弃，省去格式化开销。
- `va_start/vsnprintf/va_end`：C 变参函数的用法，把 `...` 格式化成字符串。
- **异步模式**：`log()` 只把格式化好的行 `push_back` 进队列（加锁），然后 `notify_one` 唤醒写线程。**I/O 不在业务线程做**，日志不阻塞推理/编码。
- **同步模式**：直接写。

**面试点**：异步日志的收益——日志 I/O（写磁盘）很慢，如果同步写会拖慢业务线程；异步让业务线程只做"入队"这个轻量操作，I/O 交给后台线程。

### 2.2.4 workerLoop（消费者，批量写）

```cpp
void Logger::workerLoop() {
    while (running_.load()) {
        std::deque<std::string> batch;
        {
            std::unique_lock<std::mutex> lock(mutex_);
            cv_.wait(lock, [this] { return !queue_.empty() || !running_.load(); });
            batch.swap(queue_);                 // O(1) 换出整个队列
        }
        std::lock_guard<std::mutex> fLock(file_mutex_);
        for (const auto& line : batch) writeLine(line);   // 批量写
    }
    // 退出前清空残留
    std::lock_guard<std::mutex> fLock(file_mutex_);
    while (!queue_.empty()) { writeLine(queue_.front()); queue_.pop_front(); }
}
```

**逐行讲解**：
- `cv_.wait(lock, predicate)`：队列空且未停止时阻塞。
- `batch.swap(queue_)`：**swap 是 O(1)**（只交换两个 deque 的内部指针），把整个队列换到局部 `batch` 里，**一次锁就取走所有日志**，减少锁竞争。
- 批量写：一次 I/O 写多行，减少系统调用次数。
- 退出前清空残留队列，避免丢失最后几条日志。

**面试点**：`batch.swap(queue_)` 的巧妙之处——swap 不拷贝（O(1)），锁内只做 swap 这个轻操作，真正的 I/O 在锁外做，缩短临界区。

### 2.2.5 文件轮转 rotateIfNeededLocked

```cpp
void Logger::rotateIfNeededLocked() {
    if (!fp_ || max_size_ == 0) return;
    long pos = std::ftell(fp_);
    if (pos < 0 || (uint64_t)pos < max_size_) return;   // 没超限

    std::fclose(fp_);
    std::remove((file_ + "." + std::to_string(backup_count_)).c_str());  // 删最旧的
    for (int i = backup_count_ - 1; i >= 1; --i) {
        std::rename(file_ + "." + i, file_ + "." + (i + 1));   // .N -> .N+1
    }
    std::rename(file_.c_str(), (file_ + ".1").c_str());         // 当前 -> .1
    fp_ = std::fopen(file_.c_str(), "a");                       // 重新打开
}
```

**逐行讲解**：文件超过 `max_size_` 就轮转。流程：删最旧（`.3`）→ 从后往前把 `.2→.3`、`.1→.2`（**从后往前避免覆盖**）→ 当前文件重命名 `.1` → 重新打开新文件。这样最多保留 `backup_count_` 份历史日志。

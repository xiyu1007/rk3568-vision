## 一、这个项目在做什么

一句话：**在 RK3568 边缘设备上，把摄像头画面做 AI 目标检测（YOLOv5），再把带检测框的画面用 H.264 编码后推流到 RTMP 服务器（或存成 MP4）。**

```
IMX415 摄像头
    │ MIPI CSI
    ▼
ISP（3A：自动白平衡/曝光/增益，把 raw 变成 NV12）
    │ DMA buffer
    ▼
V4L2 采集（mmap 零拷贝）
    │ Frame（NV12）
    ▼
稳帧器（25fps 节拍，快了丢帧/慢了补帧）
    │
    ▼
RGA 前处理（NV12 → RGB letterbox 640×640）
    │
    ▼
RKNN/NPU 推理（YOLOv5 INT8 量化）
    │ 检测框
    ▼
NV12 画框 + H.264 编码（MPP 硬编优先 / libx264 软编回退）
    │ AVPacket（H264）
    ▼
FLV 封装（补静音 AAC）→ RTMP 推流 → mediamtx → VLC/ffplay 拉流
                         └→ MP4 录制（本地文件）
```

## 二、7 个线程

程序运行时，一共 7 个线程在跑，线程间**只用有界环形缓冲（RingBuffer）+ 条件变量**通信：

| 线程 | 函数 | 从哪个队列取 | 放进哪个队列 |
|------|------|------------|------------|
| 采集线程 | `CameraSource::CaptureLoopV4l2/Mp4` | —（摄像头/文件） | `capture_queue_` |
| 稳帧线程 | `Pipeline::PacerLoop` | `capture_queue_` | `inference_queue_` |
| 推理线程 | `Pipeline::InferenceLoop` | `inference_queue_` | `encode_queue_` |
| 编码线程 | `Pipeline::EncodeLoop` | `encode_queue_` | `push_queue_` / `record_queue_` |
| 推流线程 | `Pipeline::PushLoop` | `push_queue_` | —（RTMP） |
| 录制线程 | `Pipeline::RecordLoop` | `record_queue_` | —（MP4 文件） |
| 监控线程 | `Pipeline::MonitorLoop` | — | —（周期打印） |

画成数据流图：

```
采集线程 ──cap_q──▶ 稳帧线程 ──inf_q──▶ 推理线程 ──enc_q──▶ 编码线程
                                                            │
                                          ┌─────────────────┴──────────────┐
                                       push_q(16)                    record_q(64)
                                          │                              │
                                          ▼                              ▼
                                     推流线程(RTMP)                 录制线程(MP4)
```

（还有 Logger 的后台写线程，共 8 个，但那个是日志基础设施，不算业务线程。）

## 三、一帧数据的完整生命周期（面试必背）

以「摄像头检测推流」为例，一帧 NV12 数据从摄像头到网络，走完下面 7 步：

1. **采集**：摄像头把 NV12 帧写进内核 DMA buffer，采集线程 `poll` 等到就绪后 `DQBUF` 取出 buffer，**不拷贝数据**，用 mmap 映射的虚拟地址构造 `Frame`，然后回调里 `capture_queue_.Push(frame)`。

2. **稳帧**：稳帧线程从 `capture_queue_` 取帧，按 25fps 节拍输出（摄像头快了就丢、慢了就补上一帧），`inference_queue_.Push(frame)`。

3. **推理前处理**：推理线程调 `Inferencer::Detect`，RGA 硬件把 NV12 转成 RGB 并 letterbox 缩放到 640×640。

4. **NPU 推理**：`rknn_inputs_set → rknn_run → rknn_outputs_get`，拿到 INT8 输出，NEON 反量化成 float，YOLOv5 解码 + NMS 得到检测框，写回 `frame->detection`。

5. **画框 + 编码**：编码线程 `DrawBoxesOnNv12` 在 NV12 的 Y 平面上画白框，然后送编码器（MPP 硬编优先），得到 H.264 的 `AVPacket`。

6. **分发**：`DispatchPacket` 把编码包分发到 `push_queue_`（推流）和 `record_queue_`（录制）。

7. **推流**：推流线程把 H.264 包经 `Muxer` 封装成 FLV（补静音 AAC），`av_interleaved_write_frame` 通过 RTMP 协议推到 mediamtx，拉流端解码播放。

**关键设计**：
- 每步之间隔着队列，所以是**异步**的，各阶段速度不一致也不会互相阻塞。
- 队列满了**丢最旧帧**，保证推出去的一定是最新画面，延迟不累积。
- 采集是**零拷贝**（mmap 引用 DMA buffer），全链路唯一的 memcpy 在稳帧器的 `CloneFrame`（补帧需要私有副本）。

## 四、三大设计模式/原则

1. **回调解耦**：`CameraSource::RegisterFrameCallback` 注册回调，采集线程回调里只入队不干活。采集模块完全不知道下游是推理还是编码，换实现不用改采集。
2. **零拷贝**：V4L2 `mmap` + `EXPBUF` 导出 DMA-BUF fd，采集不 memcpy；`shared_ptr` 自定义 deleter 在引用归零时 `QBUF` 归还 buffer。
3. **线程通信**：有界环形缓冲 + 条件变量，生产者-消费者，满则丢最旧。

## 一、V4L2 视频采集

### 1.1 什么是 V4L2

Video4Linux2，Linux 内核的视频采集/输出 API。摄像头驱动（如 rkisp）通过它把采集到的视频帧交给用户空间。

### 1.2 采集标准流程

```
open("/dev/video0", O_RDWR|O_NONBLOCK)
  → VIDIOC_QUERYCAP（查能力，判断是否 MPLANE）
  → VIDIOC_S_FMT（设置像素格式 + 分辨率）
  → VIDIOC_S_PARM（设置帧率）
  → VIDIOC_REQBUFS（申请 N 个 buffer）
  → VIDIOC_QUERYBUF（查每个 buffer 的 offset/length）
  → mmap（映射 buffer 到用户空间）
  → VIDIOC_QBUF（buffer 全部入队）
  → VIDIOC_STREAMON（开始采集）
循环：poll 等待 → VIDIOC_DQBUF（出队一帧）→ 处理 → VIDIOC_QBUF（归还）
  → VIDIOC_STREAMOFF（停止）
```

### 1.3 关键概念

- **内存映射方式**：`V4L2_MEMORY_MMAP`（mmap 映射，零拷贝）、`V4L2_MEMORY_USERPTR`（用户分配）、`V4L2_MEMORY_DMABUF`（DMA-BUF）。
- **多平面 MPLANE**：`V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE`，一个 buffer 多个平面（Y 和 UV 分开）。rkisp 用这个。
- **VIDIOC_EXPBUF**：把 buffer 导出成 DMA-BUF fd，跨设备共享（给 RGA/MPP）。

### 1.4 面试要点

- 为什么 `mmap` 是零拷贝？内核 DMA buffer 映射到用户空间，用户直接读写，不经过 CPU memcpy。
- `O_NONBLOCK` + `poll` 为什么？非阻塞打开 + poll 限时等待，让采集线程能周期性检查退出标志（优雅退出）。

## 二、DMA-BUF 零拷贝

### 2.1 DMA 是什么

Direct Memory Access，硬件（摄像头、NPU、RGA、MPP）直接读写内存，不经过 CPU。CPU 只需配置好 DMA 描述符，数据搬运由 DMA 控制器完成。

### 2.2 DMA-BUF

Linux 的 buffer 共享框架。一个 buffer 用一个 **fd** 标识，可以在不同设备/进程间共享**同一块物理内存**，不需要 CPU 拷贝。

### 2.3 本项目零拷贝链路

```
摄像头 DMA buffer ──(mmap)──▶ 用户空间虚拟地址 ──(引用，不拷贝)──▶ Frame
                                      │
                                      └──(EXPBUF 导出 fd)──▶ RGA/MPP 直接用 fd
```

### 2.4 零拷贝 vs 拷贝

| 方式 | CPU 参与 | 延迟 | 适用 |
|------|---------|------|------|
| 零拷贝（mmap/dmabuf） | 否 | 低 | 大数据量、实时场景 |
| memcpy 拷贝 | 是 | 高 | 数据量小、需要独立副本 |

## 三、FFmpeg 推流

### 3.1 FFmpeg 是什么

音视频处理的瑞士军刀，提供库（libavcodec/libavformat/libavutil/libswscale）和命令行工具。

### 3.2 推流封装流程

```
avformat_alloc_output_context2（分配输出上下文，format=flv, url=rtmp://...）
  → avformat_new_stream（创建视频流，设 codec 参数 + time_base + extradata）
  → avio_open（打开输出）
  → avformat_write_header（写 FLV 头）
循环：av_interleaved_write_frame（按 DTS 交织写音视频包）
  → av_write_trailer（写尾）
```

### 3.3 关键概念

- **time_base**：时间基，pts/dts 的单位。FLV 强制毫秒（1/1000）。
- **av_packet_rescale_ts**：把包的时间戳从源 time_base 换算到目标 time_base。
- **av_interleaved_write_frame**：按 DTS 顺序交织写音视频（内部有 max_interleave_delta 缓冲）。
- **extradata**：SPS/PPS（AVCC 格式），FLV/RTMP 解码器需要它初始化。

### 3.4 面试要点

- RTMP 基于 TCP，实时性较好（直播常用），但不是最低延迟（WebRTC/SRT 更低）。
- 时间戳不对齐会导致 A/V 错位、拉流端缓冲。

## 四、RKNN / NPU / 量化

### 4.1 NPU 是什么

神经网络处理器，专为神经网络的大量乘加运算（MAC）优化。RK3568 有 0.8~1 TOPS 的 int8 算力。

### 4.2 RKNN 框架

Rockchip 的推理框架。流程：
```
rknn_init(加载 .rknn 模型) → rknn_query(查 IO) → rknn_inputs_set(设输入)
→ rknn_run(推理) → rknn_outputs_get(取输出) → rknn_outputs_release
```

### 4.3 量化（Quantization）

把 float32 权重/激活映射到 int8，公式：
```
q = round(x / scale) + zero_point      # 量化
x = (q - zero_point) * scale           # 反量化
```

- **对称量化**：zero_point = 0，映射对称（如 [-127, 127]）。
- **非对称量化**：zero_point ≠ 0，映射非对称（如 [0, 255]）。
- **好处**：模型体积 1/4，NPU int8 算力远高于 float，推理更快更省电。
- **代价**：精度略降（INT8 只有 256 个取值）。

### 4.4 面试要点

- 为什么 NPU 用 int8？硬件 int8 算力高、内存带宽省，边缘设备算力有限。
- 量化后精度为什么能接受？神经网络对权重/激活的微小扰动不敏感（鲁棒性）。

## 五、RK3568 部署

### 5.1 RK3568 是什么

Rockchip 的四核 Cortex-A55 边缘计算芯片，带 **1 TOPS NPU**、RGA 2D 加速器、VPU（MPP 硬编解码）。

### 5.2 部署步骤

1. 交叉编译（x86 上 `make CROSS_COMPILE=aarch64-linux-gnu-`）或板端原生编译。
2. 拷贝可执行文件 + 三方库（third_lib）到板端。
3. 板端跑 `./install.sh`（一键部署 + 编译 + 运行）或直接运行。
4. mediamtx 起 RTMP 服务器，拉流端 VLC/ffplay 验证。

### 5.3 交叉编译的坑

- **GLIBC 版本**：交叉工具链的 GLIBC 必须 ≤ 目标板端（旧版编译、新版运行兼容，反之不行）。
- **动态库依赖**：FFmpeg 等三方库的 arm64 版本要放进 sysroot。
- **--allow-shlib-undefined**：交叉链接时 FFmpeg 引用的传递依赖（libtheora/libvorbis 等）不在 sysroot，放行，运行时由板端解析。

## 六、多线程 / CAS / mutex / shared_ptr

### 6.1 生产者-消费者模型

经典并发模型：生产者生产数据放入队列，消费者从队列取出处理。用**有界队列**解耦两端速度差异。

### 6.2 mutex（互斥锁）

```cpp
std::mutex m;
std::lock_guard<std::mutex> lock(m);   // RAII，作用域结束自动解锁
std::unique_lock<std::mutex> ul(m);     // 可手动 lock/unlock（条件变量需要）
```

### 6.3 条件变量

```cpp
std::condition_variable cv;
cv.wait(ul, []{ return condition; });   // 释放锁 + 阻塞，唤醒后重新加锁 + 查谓词
cv.notify_one();  // 唤醒一个
cv.notify_all();  // 唤醒所有
```

### 6.4 CAS（Compare-And-Swap）与 atomic

```cpp
std::atomic<int> counter{0};
counter.fetch_add(1);   // 原子自增，底层是 CAS/LDXR-STXR
```

- **CAS 语义**：`compare_exchange_strong(expected, desired)` —— 若内存值 == expected，则写 desired 并返回 true；否则把内存值写入 expected 返回 false。
- **无锁 vs 加锁**：atomic 对单变量用 CPU 原子指令，无锁、开销小；复杂操作仍需 mutex。
- **ABA 问题**：CAS 的无锁结构（如无锁栈）可能遇到 ABA 问题（值从 A→B→A，CAS 误判没变），需要加版本号/引用计数解决。

### 6.5 shared_ptr 自定义 deleter

```cpp
std::shared_ptr<Frame> f(new Frame, [](Frame* p){ delete p; /* 额外清理 */ });
```

- **引用计数**：shared_ptr 内部维护引用计数，归零时调 deleter。
- **自定义 deleter**：除了 delete，还能做额外动作（归还 buffer、关闭 fd 等），实现 RAII 管理 C 资源。
- **循环引用**：shared_ptr 循环引用会导致内存泄漏（引用计数永不归零），要用 weak_ptr 打破。

## 七、其他知识点

### 7.1 YOLOv5 后处理

- **输出头**：3 个尺度（stride 8/16/32）。
- **anchor**：先验框，预测值是对 anchor 的缩放。
- **NMS**：按 IoU 抑制重叠框。
- **letterbox**：等比缩放 + 灰边填充到 640×640。

### 7.2 NEON SIMD

ARM 的 SIMD 指令集，128 位寄存器，一次处理 4 个 float 或 16 个 int8。`#include <arm_neon.h>`。

### 7.3 有界环形缓冲

固定数组 + 头尾指针 + 取模回绕，满则丢最旧。不动态扩容、无内存碎片、缓存友好。
